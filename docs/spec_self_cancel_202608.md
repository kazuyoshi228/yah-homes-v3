# 仕様書：ゲストによるセルフキャンセル（MS4）

作成 2026-08-08 ／ 状態：**承認待ち**
関連：`docs/design_booking_p1_v4.md` §4・§6・§8-5

---

## 1. なぜ必要か

現状はすべて人手です。ゲストは My Page からもメールからも「お問い合わせください」に誘導され、オーナーが `/admin/bookings` で返金操作をして完了します。

この形には3つの問題があります。

- **深夜・休日に止まる。** 返金の実行はオーナー1人に依存しており、無料期限の直前に申し出があっても間に合わない場合がある
- **無料期限の判定が人の解釈に委ねられる。** 「メールを送った時刻」と「処理した時刻」がずれると、どちらを基準にするか揉める
- **OTAとの体験差が大きい。** Airbnb・Booking.com は数クリックで完了する。直販だけ「メールで相談」は、直販を選ぶ理由を1つ削る

一方で、**セルフキャンセルは金銭が動く操作**です。誤操作・二重実行・不正の余地を潰す設計が要ります。

---

## 2. 現状（実装済みの部品）

| 部品 | 状態 |
|---|---|
| 無料キャンセル期限 `freeCancelUntilAt` | 予約作成時に確定。**チェックイン日の7日前 00:00 JST**（例：9/16 チェックイン → 9/9 00:00 JST まで無料） |
| Stripe 返金 | `refunds.create`（確定済み）／`paymentIntents.cancel`（オーソリのみ）を実装済み |
| Beds24 取り消し | `cancelBeds24Booking()` を実装済み（status → cancelled） |
| 日付ロック解放 | `releaseInventoryLocks()` を実装済み |
| 状態遷移 | `transition()` による CAS（status + stateVersion）を実装済み |
| 監査ログ | `audit_logs` に金銭操作を記録 |

**足りないのはゲスト向けの入口と、期限判定・返金額計算のサーバー実装だけ**です。土台は返金機能でそろっています。

> ⚠️ 表記の不一致：特商法とFAQには「**8日前**まで無料」と書きましたが、実装は「**7日前 00:00 JST**」です。9/16 チェックインなら 9/9 00:00 まで＝実質 9/8 いっぱい、で辻褄は合いますが、**表記を「チェックイン日の7日前 00:00（日本時間）まで」に統一する**か、実装を8日前に変えるかの判断が要ります（§8 要決定①）。

---

## 3. スコープ

### やること
- My Page からのキャンセル実行（本人確認つき）
- サーバー側での期限判定・返金額計算・Stripe返金・Beds24取り消し・ロック解放
- ゲストと運営への通知メール
- 計測イベント

### やらないこと（今回の範囲外）
- **日程・人数の変更**（キャンセル＋取り直しで運用。理由は §9）
- 部分返金の任意入力（オーナーの `/admin/bookings` は従来どおり残す）
- OTA経由予約のキャンセル（各プラットフォームの管轄）

## 4. キャンセル料の規定

| 申し出のタイミング | キャンセル料 | 返金額 |
|---|---|---|
| `freeCancelUntilAt` 以前 | ¥0 | 全額 |
| `freeCancelUntilAt` 以降 | 宿泊料金の全額 | ¥0 |
| 無連絡不泊 | 宿泊料金の全額 | ¥0 |

**判定はサーバー時刻で行う。** クライアントの時計は信用しない。境界は `Date.now() < freeCancelUntilAt` の厳密比較。

**期限後のキャンセルもゲスト自身で実行できる**ようにする。返金は発生しないが、部屋を早く解放できるため運営側の利益になる。画面には「返金はありません」を明示し、二重の確認を挟む。

## 5. 画面（My Page）

### 5-1 ボタンの状態

| 予約の状態 | 表示 |
|---|---|
| CONFIRMED かつ 無料期間内 | 「このご予約をキャンセルする」＋「◯月◯日 ◯時まで無料」 |
| CONFIRMED かつ 期限後 | 「このご予約をキャンセルする」＋「キャンセル料 ¥XX,XXX（返金はありません）」 |
| チェックイン日を過ぎた | ボタンを出さない |
| CANCELLED | ボタンを出さない。「キャンセル済み」バッジのみ |
| それ以外（手続き中・要対応） | ボタンを出さない。問い合わせへ誘導 |

### 5-2 確認ダイアログ

押した直後に実行しない。**返金額を明示した確認画面**を挟む。

```
このご予約をキャンセルします

  yah.homes kiyokawa
  2026-09-16 → 2026-09-17（1泊・4名）
  予約番号 HW28ZU1R

  お支払い済み金額      ¥38,800
  キャンセル料              ¥0
  ─────────────────────────
  ご返金額              ¥38,800

  ご返金はご利用のカードへ返金処理を行います。カード会社の
  処理により、反映まで数日から1か月程度かかる場合があります。
  この操作は取り消せません。

  [ キャンセルを確定する ]   [ やめる ]
```

期限後は「キャンセル料 ¥38,800／ご返金額 ¥0」と表示し、ボタン文言を「返金なしでキャンセルする」に変える。

### 5-3 実行後

その場でカードを `CANCELLED` に更新し、結果を表示する。ページ遷移はしない。

## 6. サーバー（`accountApi` に `action: "cancel"` を追加）

### 6-1 手順

```
本人確認（IDトークンのuid == 予約のuid）
  ↓ 不一致なら 403
状態確認（CONFIRMED のみ許可）
  ↓ それ以外は 409
チェックイン日を過ぎていないか
  ↓ 過ぎていたら 409
サーバー時刻で返金額を決定
  ↓
Firestore を CANCELLING に遷移（CAS・二重実行の防止）
  ↓
Beds24 の予約を取り消す
  ↓ 失敗 → MANUAL_REVIEW ＋ 運営へ通知（返金は行わない）
Stripe 返金（返金額 > 0 のとき）
  ↓ 失敗 → MANUAL_REVIEW ＋ 運営へ通知
日付ロックを解放
  ↓
CANCELLED に遷移・audit_logs 記録
  ↓
ゲストへキャンセル確認メール／運営へ通知メール
```

**順序の理由**：先に Beds24 を取り消すことで、返金が通ったのに部屋が押さえられたままという状態を避ける。逆順だと「返金済みだが売れない部屋」が残る。Beds24の取り消しに失敗した場合は返金を行わず人が判断する。

### 6-2 二重実行の防止

`CANCELLING` を新設し、`transition()` の CAS で入口を1つに絞る。連打・別タブ・通信リトライで返金が2回走らないようにする。

### 6-3 レート制限

同一 uid から 1分あたり5回まで。超過は 429。

## 8. 要決定（着手前に確認が必要）

1. **無料期限の表記** — 「7日前 00:00 JST」に統一するか、実装を「8日前 23:59 JST」に変えるか。**推奨：実装を「チェックイン日の8日前 23:59 JST」に変更。** 特商法・FAQ・決済画面の既存表記と一致し、ゲストにも直感的
2. **期限後のセルフキャンセルを許可するか** — **推奨：許可**（返金なしと明示のうえ）。部屋を早く解放できる
3. **キャンセル理由の任意入力** — 集めるか。**推奨：任意の自由記述1つだけ**。必須にしない
4. **チェックイン当日・滞在中の扱い** — ボタンを出さない方針でよいか（問い合わせのみ）

---

## 9. 「変更」を範囲外にした理由

日程・人数の変更は、実質「元の予約をキャンセルして新しい予約を作る」操作です。差額の精算（追加課金／一部返金）、在庫の同時押さえ、Beds24側の2操作が絡み、失敗時の巻き戻しが一段複雑になります。

キャンセルが安定して回ってから、別途仕様を起こすのが安全です。当面は「キャンセル→取り直し」で運用し、無料期間内なら金銭的な不利益は生じません。**この運用方針を My Page とFAQに明記する**必要があります。

## 10. 受け入れテスト

| シナリオ | 合格条件 |
|---|---|
| 無料期間内にキャンセル | 全額返金・Beds24から消える・ロック解放・両者にメール |
| 期限後にキャンセル | 返金¥0・Beds24から消える・ロック解放・メールに「返金なし」 |
| 確認ダイアログでやめる | 何も起きない |
| ボタン連打 | 返金は1回だけ。2回目は409 |
| 他人の予約IDを直接叩く | 403。データは変化しない |
| Beds24取り消しが失敗 | 返金は実行されない。MANUAL_REVIEW＋通知 |
| Stripe返金が失敗 | MANUAL_REVIEW＋通知。Beds24は取り消し済みとして記録 |
| キャンセル後に同じ日程を検索 | 再び予約できる |
| チェックイン後 | ボタンが出ない |

## 11. 工数の目安

| 項目 | 規模 |
|---|---|
| `accountApi` の cancel アクション | 中（状態遷移・返金・Beds24・ロック） |
| My Page の確認ダイアログ・状態別表示 | 中（5言語） |
| キャンセル確認メール（HTML・5言語） | 中（確定メールの部品を流用） |
| 計測イベント（`cancel_started` / `cancel_confirmed` / `cancel_failed`） | 小 |
| テスト | 中（テスト物件で全シナリオ） |

既存の返金処理・Beds24取り消し・ロック解放が動いているため、**新規に書くのは入口と判定ロジックが中心**です。
