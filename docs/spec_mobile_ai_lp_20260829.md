# 仕様書: モバイルは「AIに聞く1画面」にする（yah.OS ホーム）

- 起票: 2026-08-29 発注者「モバイルでアクセスした場合、AIが答えるウィンドウだけのシンプルなLPにできますか？
  LPのみで大丈夫。AIが答えるベースで全て把握する形に」「編集作業はPCでやれば良い」「ロゴは設置しよう」
  「AIの答えは下に展開されていくように」
- 対象: `index.html`（ホーム）と `os.css` のメディアクエリのみ。**カードHTMLは1枚も触らない**
- 担当: 共有部スレッド。承認後に着手（この文書は承認待ち）

## 1. 決めたこと

**モバイル（画面幅 ≤700px）のホームは、AIに聞く画面にする。** 表・カード一覧・今日ボードの行は出さない。
数字は「AIに聞いて、文章で受け取る」。**編集・検収・承認はPCで行う**（モバイルは見る/聞く専用）。

PC（≥701px）は**現状のまま一切変更しない**。今日ボードもカード一覧もそのまま。

## 2. 画面（モバイル）

上から順に、この3つだけ。

1. **ロゴ** … yah.OS ロックアップ（`os-nav.js` の LOGO 定数と同一。既存の `.osnav-toplogo` を流用）。
   タップでホーム再読込。右端にログイン状態のアイコン、左端にハンバーガー（§4）
2. **今日の一行** … 例「今日の要対応 4件・タップで内容を聞く」。
   health の warn 件数だけを出す（**内訳は書かない**——文章はAIが答える）。
   - 警告0件のときは「今日は要対応なし」
   - health 未取得（未ログイン）のときは非表示
   - **タップすると `今日やることを教えて` を質問として自動送信**（プリセット質問。AIが台帳を読んで文章で返す）
3. **AI質問窓** … 入力欄は**画面下に固定**。回答は**入力欄の上へ、古い順に下へ積み上がる**（既存 `.ask-log` と同じ向き）。
   - 新しい回答が来たら**その先頭が見えるところまで自動スクロール**（読み始めの位置に合わせる。末尾ではない）
   - 送信中は「考え中…（データを見に行っています）」を最後の吹き出しとして出す（既存）
   - 失敗時は質問を入力欄に戻す（P1で実装済み）
   - キーボード表示で入力欄が隠れないよう、高さは `100dvh` 基準にする

## 3. 出さないもの（モバイル）

- 今日ボードの表（`#home-list` の行）
- 左ナビの常時表示（ハンバーガーの中に格納。§4）
- `live-state` の文言（既に非表示）

## 4. カードへ行く導線（残す・既定では隠す）

既存のハンバーガーをそのまま使う。開くとカード一覧が出て、各カードへは従来どおり遷移できる
（カード内は現状のまま。モバイルでも表示・操作は可能だが、**編集はPC推奨**）。
AIの回答に出てくるカード名から直接飛べる導線は、今回は作らない（次段の課題）。

## 5. しないこと（今回の範囲外）

- カードHTMLの改修（モバイル最適化を含む）
- AIに操作させること（登録・検収・承認。fail-closed のまま＝人のクリックのみ）
- 音声入力の実装（OS標準キーボードの音声入力で足りる。専用の入口は段F/音声の課題として別途）
- PC側の変更

## 6. 実装方針（差分の見取り図）

- `index.html`: モバイル判定は**CSSのみ**で行う（JSで分岐しない＝PC/モバイルで同じDOMを配る）。
  - 今日ボードは `#home-list` ごと `@media (max-width:700px) { display:none }`
  - 「今日の一行」は新規要素。件数は既存の health 取得結果（`H.checks` の warn 数）から出す。**新しいAPIは作らない**
  - プリセット質問は既存の送信関数を呼ぶだけ（新しい経路を作らない）
- `os.css`: `@media (max-width: 700px)` に、ホーム専用のレイアウト（ロゴ・一行・チャット）を追加
- 追加のライブラリ・ビルドは無し（既定方針どおり）
