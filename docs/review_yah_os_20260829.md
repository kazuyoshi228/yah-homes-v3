## 改善点（優先順）

### ① addSince が1棟も入っていない（最優先・データ1行で直る）
`facts.ts:43` は棟ごとの `addSince`（開業日）で「取得投資」と「追加投資」を分ける設計だが、
**実データでは5棟すべて未設定**。コードは安全側に倒れて**全件を取得投資として扱う**ため壊れはしないが、
稼働中の清川・高砂で今後発生する追加投資も取得原価に混ざり続け、投資額・利回りが実態から離れていく。
2026-08-28 に外した「時限爆弾」は、**データが入っていないため実質まだ動いていない**。
→ 清川・高砂の開業日を properties に入れるだけ（作業1分）。準備中の2棟は入れなくてよい。

### ② AIの回帰テストが無い（今日の誤答が示したもの）
実機で「タスクは？」と聞いて `list_overdue_jobs` だけを見て「ありません」と答えた。指示文で直したが、
**同じ劣化がまた起きても誰も気づかない**。固定の質問3〜5問（「今日やることは」「先月の売上は」
「高砂の8月の光熱費は」）を毎朝1回投げ、**参照した道具名と回答の空でないことだけ**を検査して
heartbeats に記録すれば、AIの品質が沈黙で劣化しなくなる。実装半日・費用は月数十円。

### ③ 監視と復元の証跡が無い（事故ったときだけ困る類）
- GCP予算アラート（5分）: 課金の暴走に気づける
- Error Reporting（無料枠）: 例外がログに埋もれている現状の解消
- **バックアップの復元演習を1回**やって手順を docs に残す。「取れている」と「戻せる」は別物

### ④ 現金残高カード（建設完了の最後のピース）
`cash` は0件。月次の残高スナップショットが入れば、「稼ぎ」と「手元」が同じ画面で繋がる。
取込パイプ（メール転送→AI読取→検収）は既に動いているので、**入口は作らず流用できる**。

### ⑤ docs 115本に目次が無い
仕様書・指示書・下書きが同じ場所に混在し、どれが現行仕様か外部からは判別できない。
`docs/README.md` に「現行仕様／完了した指示書／下書き」の3分類で並べるだけで、
引き継ぎとPEデューデリの手間が変わる。
