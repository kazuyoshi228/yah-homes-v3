- 前提: データの器としては完成度が高い(清川81.4)。以下は「器」ではなく「見せ方と出口」の改善

## 優先順

### A. 「この棟の宿題」ボックス(効果◎・工数小)

いちばん効く割に半日かからない。未取得書類2件・欠測2件・概算9件・監査⚠は
**全部バラバラのタブに散っていて、「次に何をすべきか」を知るには7タブ巡回が要る**。

属性タブの上(または1Pager採点表の下)に、導出だけで作れる:

```
この棟の宿題(全て既存データから導出・保存しない)
・追加必須書類: 未取得7件(うち必須3: 検査済証・登記事項証明書・旅館業許可証)
・概算のまま: 9件(見積が来たら年割りが実額になる)
・欠測: 給湯器の型番・洗濯機の取引No
・定期作業: 2026-11 契約不適合の総点検(期限2027-01-09)
```

材料は DATA に全部ある(requiredDocs / items.estimate / noLifespan / schedules)。
OS側P1(今日ボード)の棟版であり、P1より先にここでパターンを作れる。

### B. タブの族分け(効果◎・工数中)

タブが17個まで増えた(今日 建築確認・内装 を足したのは私)。3つの族に整理する:

| 族 | タブ |
|---|---|
| 資産 | 属性・建築確認・書類一式・追加必須書類 |
| 金 | 投資額・追加投資額・更新計画・作業 |
| 物 | 設備・家具・カーテン・建材・備品・工事・内装 |

「物」の7タブは equipment の group 表示(dyn機構)と実質重複しており、
**dyn機構に寄せればタブ数を半減できる**。見出し行(subnav-cap)は既にあるので並べ替えが主。

### C. 1PagerのPDF出力(効果◎・工数中)

清川は「DD資料の8割が即日出せる」状態になった。**出口が無いのが勿体ない**。
1Pager(投資・利回り・含み益・採点表)+書類一覧を1枚のPDFに落とすボタン。
銀行(借換・次の融資)・事業承継・Airstar交渉で、そのまま差し出せる紙になる。
実装は window.print() + 印刷CSS で足りる(サーバ不要)。

### D. 外観写真1枚(効果○・工数小)

カードに写真がゼロ。保管庫に外観図はあるが、実物の写真1枚が1Pagerの頭にあるだけで
認知速度が違う(竣工写真は requiredDocs で追跡中——届いたら1Pagerに出す配線だけ先に)。

### E. 保存後の差分適用(効果○・工数小)

属性保存・年数変更のたびに `api("properties")` を**全棟まるごと再取得**している。
保存結果を DATA に差分適用すれば、保存→表示更新が体感ゼロになる。
