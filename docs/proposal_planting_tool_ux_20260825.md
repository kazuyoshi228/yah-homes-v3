# 提案書 — 植栽ツールを「現場で使える」ものにする改善案

- 状態: **P1〜P4・P8〜P10 実装済み（2026-08-25）**。P5（.ics）・P6（インライン確認）は保留、
  P7（現場情報の追記）は不要と判断（すでに実績があり業者が把握済み・2026-08-25 発注者）
  - P1 写真の縮小はブラウザ実測で確認（4000×3000 → 1600×1200・86ms）
- 起票: 2026-08-25
- 対象: 業者ページ niwa.html ／ 植栽メンテカード planting.html ／ plantingCal 関数
- 前提: 基本機能（カレンダー・選択・取消・報告・通知）は本番稼働中。ここでは使い勝手だけを扱う

---

## 0. 評価の視点

このツールの価値は**LINEの往復を減らすこと**にある。
なので「まだLINEが必要な場面」と「現場で失敗しうる場面」を潰すのが改善。
見た目を整えることではない。

現状で **LINEが残る場面**:
1. 写真の送信が失敗したとき（後述P1）
2. 作業日を業者が自分のカレンダーに入れ忘れたとき
3. 請求書のやりとり
4. 鍵・水道・ゴミの扱いを聞くとき（ページに書いていない）

---

## 1. 優先度つき改善案

### P1. 写真を送信前に縮小する（**最重要・現場が壊れる唯一の箇所**）

いまは選んだ写真を**そのままbase64でPOST**している（`b64(f)` に縮小処理なし）。
現場のiPhone写真は1枚3〜5MB。base64化で約1.33倍に膨らむため、
**5枚選ぶと20MB超のリクエスト**になり、Cloud Functionsの上限（10MB）を超えて失敗する。
しかも失敗するのは「作業が終わって報告する瞬間」＝一番めんどうな時。

対策: canvasで長辺1600pxにリサイズしてJPEG品質0.7で送る（1枚300KB前後）。
実装は20行ほど。**これをやらないと報告機能は実質使えない。**

### P2. 送信の失敗に強くする（現場は電波が悪い）

- 送信ボタンを押した後の失敗が「送信できませんでした」で終わり、書いた文章が消えかねない
- 対策: 入力内容を `localStorage` に自動保存し、失敗しても再送ボタンで復帰できるようにする
- 併せて2回まで自動リトライ（指数バックオフ）

### P3. 「飛び込み作業」を報告できるようにする

サーバ側は**選択なしの報告に対応済み**（vendorReported付きの突発ジョブを作る）のに、
画面が `DAYS.filter(d => d.taken)`＝選択済みの日しか選択肢に出さないため**塞がっている**。
台風後の枝処理など、予定外に入った作業が記録できない。

対策: 日付の選択肢に「その他の日」を足し、選ぶと日付入力欄が出る。

### P4. 取消の誤タップを防ぐ

選択済みの日を押すと取消になるが、**見た目が他と同じカードで押せてしまう**。
現場で「次の日程を見ようとして触って消す」事故が起きうる。

対策: 選択済みカードは押せなくし、カードの中に小さく「取消」リンクを置く。

### P5. 選択したらカレンダーに入れられるようにする

日を押して確定した後、業者は自分のスケジュールに転記する必要がある（＝忘れる／LINEで確認が来る）。

対策: 確定後に **「カレンダーに追加」ボタン**（.icsファイルを生成してダウンロード）。
iPhoneでもAndroidでもそのまま予定に入る。**LINE往復が1つ減る効果が大きい割に実装は軽い。**

### P6. 確認ダイアログをページ内に置き換える

`confirm()`/`prompt()` はスマホで唐突に出るうえ、押し間違いが起きやすい。
対策: カードの下に「この日で確定する / やめる」の2ボタンを出すインライン確認にする。

### P7. 現場の疑問をページに書く（鍵・水道・ゴミ・駐車）

いまの注意書きは3行だけ（清掃在室・ゲスト対応不要・報告のしかた）。
**実際に業者が困るのは「水道は使えるか」「切った枝はどこに捨てるか」「車はどこに停めるか」**。
清川は敷地内に車庫11.18㎡があるが軽・小型向き。この情報が無いと必ずLINEで聞かれる。

対策: 注意書きに4項目を追記（内容は発注者に確認して確定）。

### P8. 報告フォームを最初から開いておく（作業当日だけ）

いまは「完了報告をひらく」を押さないと出ない。
**今日が選択済みの日なら、最初から開いた状態**にする。作業直後の1タップを削る。

### P9. オーナー側カードに「今月の状態」を出す

植栽メンテカードはカレンダーの埋め込みと台帳が並ぶだけで、
**「今月やったのか、これからなのか」が一目で分からない**。

対策: カード上部に1行 —「今月: 8/28 に作業予定（未実施）」／「今月: 実施済み・検収待ち」。
判定は既存のジョブから導出するだけで、新しいデータは持たない。

### P10. 実施日を過ぎても報告が無いときの催促

いま入れたアラートは「当月の作業日が未選択」だけ。
**選択したのに作業されなかった／報告を忘れた**場合に気づけない。

対策: 実施予定日の翌日以降で `confirmed` のままのジョブを、毎朝の点検メールに載せる。

## 2. 実装の順（推奨）

| 順 | 項目 | 工数 | 理由 |
|---|---|---|---|
| 1 | **P1 写真の縮小** | 30分 | これが無いと報告機能が実質死んでいる |
| 2 | **P7 現場情報の追記** | 15分 | 内容が決まればすぐ。LINEを減らす効果が直接的 |
| 3 | **P5 カレンダー追加(.ics)** | 30分 | 軽いのに効く |
| 4 | P4 誤タップ防止＋P6 インライン確認 | 1h | 事故を防ぐ |
| 5 | P3 飛び込み報告 | 30分 | サーバは対応済み・画面を開けるだけ |
| 6 | P2 失敗に強くする | 1h | 電波の悪い現場向け |
| 7 | P9・P10 オーナー側 | 1h | 運用が回り始めてからで良い |
| 8 | P8 フォーム自動展開 | 10分 | ついで |

合計 約5時間。**1〜3（1時間15分）だけでも実用性は大きく変わる。**

---

## 3. やらないこと

- **業者ログイン・アカウント**（トークンURLで足りている）
- **チャット機能**（LINEがある。二重の連絡経路を作らない）
- **見た目の作り込み**（現状で読みやすさは足りている。飾りは価値を生まない）
- **複数業者対応**（いまは花屋アンのみ。増えたときに考える）

## 4. 発注者への確認事項（クローズ）

**不要（2026-08-25 発注者）。** すでに作業実績があり、業者が現場の勝手を把握しているため。
新しい業者に替えるときは、この4項目をページに書く必要が出る:


1. 水道は使ってよいか（外部水道あり・カクダイ立水栓）
2. 切った枝・草の処分は業者持ち帰りか、敷地に置いてよいか
3. 駐車はどうするか（敷地内車庫は軽・小型向き／来客用は南西30m先）
4. 鍵は必要か（庭作業のみなら不要のはず。要否だけ確定したい）
