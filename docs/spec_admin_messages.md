# 仕様書：/admin/messages（ゲストとのメッセージ）

作成 2026-08-12 / 状態 **承認待ち** / 前提: Beds24 での直販返信は構造的に不可（実測・Airstar確認済み）

## 1. 何を作るか

直販のお客様とのやり取りを **/admin の中で完結**させる。Beds24 に寄せるのは諦め、
Airbnb の受信箱に相当するものを自前で持つ。

```
/admin/messages
┌── スレッド一覧 ──┬── 選択したスレッド ───────────┐
│ ● 田中様  清川    │ 田中 太郎様 ／ 清川 ／ 8/17〜19 ／ A1B2C3D4 │
│   8/12 10:00      │ ─────────────────────── │
│   駐車場は…       │  お客様  8/12 10:00                      │
│                   │   駐車場は使えますか？                    │
│   Kim様  高砂     │                                          │
│   8/11 既読       │  yah.homes  8/12 10:15  杉元              │
│                   │   はい、1台分ご利用いただけます              │
│                   │ ─────────────────────── │
│                   │ [ 返信を入力 ................. ] [送信]   │
└───────────────┴──────────────────────┘
```

- 左＝スレッド一覧（未読が上・物件と日程つき）／右＝会話と返信欄。
- 送信すると **お客様へメールが届く**（yah.homes の既存HTML枠・予約情報つき）。
- お客様がそのメールに返信すると、**同じスレッドに積まれる**（§3）。
- 権限は OPERATOR 可（日々の運用）。個人情報を含むため ADMIN/OPERATOR 以外は不可。

## 2. データ

```
threads/{bookingId}
  prop / guestName / guestEmail / checkin / checkout / lang
  lastMessageAt / lastFrom: "guest"|"host" / unread: boolean / closed: boolean
threads/{bookingId}/messages/{id}
  from: "guest" | "host"
  body / at / author（hostのみ・送信者のメール）
  mailMessageId（送信・受信したメールのMessage-ID。突き合わせに使う）
```

スレッドは **予約1件につき1本**。予約確定時に自動生成する（本文0件の空スレッド）。

## 3. お客様の返信をどう取り込むか（ここが要）

自動メールの `Reply-To` を **予約ごとの専用アドレス**にする。

```
Reply-To: reply+A1B2C3D4@mail.yah.homes
```

お客様がそのまま返信すると、`+` の後ろの予約番号で**どのスレッドか一意に決まります**。
取り込み方法は2案。

| | A案：Gmail API で読む（**推奨**） | B案：受信専用サービスを使う |
|---|---|---|
| 仕組み | `contact@mail.yah.homes` の受信箱を、5分おきに Gmail API で読み、未処理を取り込む | Mailgun / Postmark 等の Inbound Parse に MX を向け、Webhook で受け取る |
| 追加費用 | なし | 月 $15〜（送信量による） |
| 必要な準備 | Google Workspace 管理画面で **サービスアカウントにドメイン全体の委任**を1回設定 | **MX レコードの変更**（メール配信の根幹を新業者に移す） |
| リスク | 委任設定を誤ると他のメールも読めてしまう（スコープを readonly + 対象1アドレスに限定して回避） | 設定を誤ると **お問い合わせメールが全部止まる** |
| 反映速度 | 最大5分 | 即時 |

**A案を推奨します。** 新しい業者もDNS変更も不要で、いま使っている受信箱をそのまま読むだけ。
5分の遅れは、宿の問い合わせ対応では実用上問題ありません。

※ Workspace の設定（ドメイン全体の委任）は**オーナーの操作**が必要です。手順書を用意します。

## 4. 通知

- 新着メッセージ → 台帳で `notifyBookings` が ON のメンバーへ通知メール（Airstar含む）。
  件名「【メッセージ】田中様（清川 8/17〜）」。本文に抜粋と /admin/messages へのリンク。
- 通知メールに返信しても取り込まない（誤操作防止のため `Reply-To` は no-reply）。
  → 返信は必ず /admin/messages から行う運用にする。

## 5. 送信するメールの体裁

既存の HTML 枠（`mailHtml`）を流用。ヘッダーに yah.homes と予約番号、本文に返信内容、
フッターに「このメールにそのままご返信いただけます」。**5言語**（予約の言語で出し分け）。

## 6. 作らないもの（v1の線引き）

- 添付ファイル（写真等）— v2。まずはテキストのみ。
- OTA予約のスレッド — Airbnb/Booking.com は Beds24 で回っているので触らない。
- 定型文の挿入・既読管理の細分化 — 運用が始まってから必要なら足す。
- リアルタイム更新 — 画面を開いたときと、30秒ごとの再取得で足りる。

## 7. 受け入れ条件

- [ ] 直販予約ごとにスレッドが自動生成される
- [ ] /admin/messages から送信するとお客様にメールが届く（5言語・HTML枠）
- [ ] お客様がそのメールに返信すると、同じスレッドに5分以内に表示される
- [ ] 新着で運営に通知が飛ぶ
- [ ] OPERATOR で閲覧・返信できる。未認証・権限外は 401/403
- [ ] メール送信ログに記録される（既存の mail_logs）
