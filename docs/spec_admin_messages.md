# 仕様書：メッセージ機能（Airbnb同等）v2

作成 2026-08-12 / 状態 **承認待ち** / 前提: Beds24 での直販返信は構造的に不可（実測・Airstar確認済み）

## 0. v1からの変更（発注者指示）

- **お客様は My Page からメッセージを送る**（メール返信ではなく）。
  → これにより **Gmail API の取り込みが丸ごと不要**になり、Workspace のドメイン委任も不要。
  受信は自社の認証済み画面から入るので、なりすまし・スパム・宛先の取り違えが構造的に起きない。
- Airbnb と同等の機能一式を実装する。

## 1. 全体像

**予約1件＝スレッド1本。** 会話が混ざらない。これが今回の要件の核心。

## 3. データと権限

```
threads/{bookingId}
  uid（予約者のFirebase UID）/ prop / guestName / checkin / checkout / lang
  lastMessageAt / lastFrom: "guest"|"host"
  unreadForGuest: number / unreadForHost: number
threads/{bookingId}/messages/{id}
  from: "guest" | "host"
  body（原文）/ bodyJa（自動翻訳・原文が日本語以外のときだけ）
  at / author（hostのみ・送信者メール）/ beds24MessageId
```

**Firestore ルール**（現在は既定deny。ここだけ開ける）

```
threads/{bookingId}
  read:  自分の予約（uid一致）または 管理者台帳のメンバー
  write: 不可（すべて API 経由）
threads/{bookingId}/messages/{id}
  read:  同上
  write: 不可
```

読み取りだけ直接許可して**リアルタイム購読**を成立させ、書き込みは必ずAPIを通す
（文字数制限・レート制限・通知・Beds24複製・翻訳をサーバ側で強制するため）。

## 4. API（`messagesApi`）

| 操作 | 誰が | 内容 |
|---|---|---|
| `send` | ゲスト（uid一致）／ADMIN・OPERATOR | 本文2,000字まで・1分5通まで。保存→通知→Beds24複製→翻訳 |
| `read` | 同上 | 自分側の未読を0に |

- ゲストは **自分の予約のスレッドにしか**送れない（uid照合）。
- 送信のたびに `mail_logs` へ記録（既存の仕組みを流用）。

## 5. 自動翻訳（Airbnb同等・この事業では特に効く）

お客様が韓国語・繁体字・タイ語で書いても、**運営画面には日本語訳を併記**する。
逆に運営が日本語で返せば、**お客様にはその方の言語の訳を併記**して届ける。

- 実装: Cloud Translation API（Google・従量課金。月数千通でも数十円規模）
- 原文は必ず残し、訳は補助として下に小さく表示（誤訳しても原文で確認できる）
- 訳の生成に失敗しても送信は成立させる

Airbnb と Booking.com のやり取りが中国語・韓国語で来ている実態（受信箱で確認済み）から、
これが無いと運営会社の負担が実際に増える。v1 に入れる。

## 6. 通知

| 誰に | いつ | 中身 |
|---|---|---|
| お客様（メール） | 運営が返信したとき | 5言語・本文の抜粋・My Page のスレッドへのリンク。**Reply-To は no-reply**（返信はMy Pageからと明記） |
| 運営（メール） | お客様が送信したとき | 台帳の `notifyBookings` 宛。抜粋と /admin/messages へのリンク |

連投対策として、同一スレッドで **5分以内の連続送信はまとめて1通**にする。

## 7. Beds24 への複製

送受信のたびに Beds24 の該当予約へ複製する（`guest` / `host`）。
**Airbnb・Booking.com・直販のすべてが Beds24 の受信箱に並ぶ**ようになり、
Airstar が「全部まとめて見る」用途に使える。複製の失敗はメッセージ機能を止めない。

## 8. 画面

**My Page（`/[locale]/account`）** — 予約カードの下に会話を追加。未読があればカードにバッジ。5言語。
**`/admin/messages`** — 左にスレッド一覧（未読が上・棟と日程）、右に会話と返信欄。
メニューの「運営管理」に追加（OPERATOR 可）。未読数はメニューのカードにも出す。

## 9. 受け入れ条件

- [ ] 予約ごとにスレッドが分かれ、他の予約の会話が混ざらない
- [ ] 双方の送信が**リロードなしで相手の画面に出る**
- [ ] 他人の予約のスレッドは読めない・書けない（uid照合・ルール・APIの三重）
- [ ] 未読バッジが双方で正しく増減する
- [ ] 相手にメール通知が届く（お客様は自分の言語で）
- [ ] 韓国語・タイ語で送ると運営画面に日本語訳が併記される
- [ ] Beds24 の受信箱に Airbnb と並んで表示される
- [ ] OPERATOR で使える。未認証・他人の予約は 401/403
