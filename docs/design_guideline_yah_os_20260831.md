# yah.OS デザインガイドライン

**バージョン 1.2.0（2026-09-01）** ／ 改訂履歴は末尾

- 起票: 2026-08-31 発注者「統一感のあるように。枠の位置・フォント・タイトルの位置・表の出し方・ボタンの色」
- **この文書がデザインのSSoT（正本）**（2026-09-01 発注者指示）。
  実装（`yah-os/os.css`）はこの文書に従う。**食い違ったら実装を直す**——
  以前は逆（実装が正）だったが、決まりが文書側にある方が守れるため入れ替えた
- **バージョンを付ける。** 決まりを変えたら末尾の改訂履歴に1行足し、番号を上げる——
  「いつ・何を・なぜ変えたか」が残らないと、後から来た人が古い画面を直してよいのか判断できない。
  番号の付け方: **大きい桁＝骨格や色など画面全体に効く変更／小さい桁＝追記・言い換え**
- **守られているかはCIが機械検査する**（`yah-os/designcheck.mjs`）。
  検査できるのは右パネル幅・`.panel2`の再定義・地色・黄系の統一・骨格の要素の5点。
  新しい決まりを足すときは、**まずこの文書に書き、次に検査へ足す**（文書に無い検査を作らない）
- 迷ったら原則ひとつ: **共通に無いものを各カードで作らない。** 必要なら os.css に足してから使う
- **上位の決まりは yah. ブランドガイドライン**（`docs/brand/brand-reference.md` ／ 一次ソース
  `Brandguidelines_yah.pdf`）。この文書はその下位——**食い違ったらブランドが優先**

## 0. ブランドとの関係（2026-08-31 に揃えた）

| 項目 | ブランドの定め | yah.OS |
|---|---|---|
| 書体（欧文） | National 2（Klim・正規ライセンス） | **自ホストで採用**（本体サイトと同一のWOFF2） |
| 書体（和文） | 游ゴシック Medium | **採用**（游ゴシック→Hiragino→Noto の順） |
| 地色 | Black `#000000` | **採用**（旧 `#0a0a0a` から変更） |
| 文字色 | White `#FFFFFF` | 採用 |
| グレー | Light Gray `#F7F7F7` / Gray `#D7D7D7` | **暗いUIのため運用値で代替**（`#1c1c1c` `#262626` `#9a9a9a` 等）。

**差し色について（重要な例外）。** ブランドは「モノクローム4色のみ。青・赤・金などの差し色はパレット外」

一方 yah.OS は**社内の運用画面**で、状態（正常／要対応／注意）を色で伝えられないと機能しない。
そこで **`#63d297` `#ef4444` `#e0b050` `#6ea8fe` を「機能色」として限定的に使う**——
装飾には使わず、意味の表示だけに使う。**顧客が見る面（yah.homes・メール本文の体裁）には持ち込まない。**
※**2026-08-31、ブランド側に「機能色の例外規定」として正式登録済み**
（`docs/brand/brand-reference.md`）。CTA Blue と同じ扱い

## 1. 骨格（枠の位置）

全カードが同じ骨格を持つ。**この順序と余白を崩さない。**

| 部位 | 値 | 備考 |
|---|---|---|
| トップバー | 高さ 49px・`padding: 0.9rem 1.5rem`・下線 `#1c1c1c` | 固定（sticky）。半透明＋ぼかし |
| 左ナビ（os-nav） | 幅 210px | 全ページ共通・`os-nav.js` が描く。カード側で書かない |
| 中央（.main） | `padding: 1.75rem 1.75rem 4rem` | 本文。最大幅はカードの性格で決める（下記） |
| 補助パネル（.aside） | 既定 260px | 左ナビの右。`.layout` に `has-aside` を付けたページだけ出る。中には `.panel2` を積む |
| 右パネル（.panel） | **既定 600px**・可変 | 詳細の表示。`position: sticky; top: 49px` |
| 中央上部のタブ帯（.main-tabs） | 最低 2.6rem | **タブの位置をページ間で揃えるため常設**。中身が無くても高さを保つ |
| 3ペインの並び | `210px / 1fr / 5px / 600px` | 5px は幅を変えるつまみ |
| 4ペイン（補助パネルあり） | `210px / 260px / 1fr / 5px / 600px` | `.layout.has-aside` |

**折りたたみ:** 1400px以下で補助パネルを隠す／1100px以下で右パネルを隠す／900px以下で左ナビも隠す／700px以下はモバイル。

**本文の最大幅**は3種類しかない。増やさない。
- 表が主役（物件・メンテナンス・定期レポート）… 制限なし（3ペインいっぱい）
- 図と数字（BS・観光客数）… `max-width: 980px`
- 読み物（マニュアル・SSoTマップ）… `max-width: 860px`

## 2. タイトルの位置

**画面の題名はトップバーのパンくずが担う。** 本文の見出しはその下。

```html
<nav class="topbar"><div class="topbar-in">
  <span class="crumb"><a href="index.html">yah.OS</a> / 財務 / <b>BS</b></span>
  <span style="margin-left:auto">…状態表示…ログインアイコン…</span>
</div></nav>
<main class="main">
  <h1 style="font-size:1.05rem">BS（貸借対照表）</h1>
  <p class="note">正本は Firestore の … ——この画面は表示だけ</p>
```

- パンくずは `yah.OS / カテゴリ / <b>カード名</b>`。カテゴリ名は左ナビの見出しと同じ語を使う
- `<h1>` は **1.05rem**（大きくしない）。カード内の節見出しは `<h2>` 0.9rem
- **h1 の直下に「正本はどこか」を1行**書く（`class="note"`）。これはyah.OSの作法——
  画面が正本ではないことを毎回明示する
- 右端は `live-state`（件数・時点）→ ログインアイコンの順。この並びを変えない

## 3. 文字

| 用途 | サイズ | 色 |
|---|---|---|
| 基準（html） | **17px** | — |
| 本文・表 | 0.85rem | `#fff` |
| 表の見出し（thead th） | 0.72rem・字間 0.15em | `#8a8a8a` |
| 補足（.note / .dim） | 0.78rem / — | `#9a9a9a` |
| タグ（.pill） | 0.7rem | `#bbb`・枠 `#333` |
| **下限** | **0.72rem** | これ未満は CI が落とす |

- 書体は **National 2 → 游ゴシック → Hiragino → Noto**（本体サイトと同一の並び・自ホスト）。
  **これ以外のWebフォントを足さない**
- 数字が縦に並ぶ列は `font-variant-numeric: tabular-nums` と `text-align: right`
- 金額は `yen()` / `man()` を使う。カードごとに書式が違うため**あえて共通化していない**——
  それぞれの流儀を守る

## 4. 色

**背景と枠**（この4つ以外の暗色を新しく作らない）

| 用途 | 値 |
|---|---|
| 画面の地 | `#000000`（ブランドの Black） |
| 区切り線・枠 | `#1c1c1c`（構造）／`#262626`（部品）／`#1e1e1e`（表の行） |
| 沈んだ面（入力欄・タブ） | `#141414` / `#1a1a1a` |
| 浮いた面（囲み・パネル） | `#101418`（枠 `#1e2630`）＝ **`.panel2` が正本**。各カードで再定義しない |

**意味を持つ色**（装飾に使わない。意味が変わるので流用しない）

| 意味 | 値 | 使う場所 |
|---|---|---|
| 正常・増加 | `#63d297` | 状態ドット緑系・前年比プラス |
| 要対応・減少 | `#ef4444`（文中は `#ff8080`） | 警告ドット・前年比マイナス |
| 注意・保留 | `#e0b050` | 印（⚑）・注記の帯 |
| 選択・強調 | `#6ea8fe` | フォーカス枠・選択中・グラフ1本目 |
| 決定ボタン | 背景 `#fff` / 文字 `#0a0a0a` | 「聞く」など主要動作 |

**状態ドット（左ナビ）**は例外的に青＝正常。`d-ok #3b82f6` / `d-warn #ef4444` / `d-na #333`。
**health から導出**し、手動の上書きは人の判断として保存する。

> **既知のばらつき（直す対象）**: 黄系が `#e0a13a`(11) `#e0a355`(12) `#e8c268`(8) `#e0b050`(2) と
> 4種類に割れている。新規は **`#e0b050`** に寄せ、触るついでに既存も置き換える。

## 5. ボタン

**種類は3つだけ。** 新しい見た目を作らない。

| 種類 | クラス | 見た目 | 使いどころ |
|---|---|---|---|
| 副操作 | `.btn-sub` | 透明・枠 `#333`・文字 `#ddd`・0.78rem | 表の行内、パネル内の操作（最も多い） |
| 主操作 | 背景 `#fff`・文字 `#0a0a0a`・太字 | 白ボタン | 画面にひとつ（送信・実行） |
| 危険 | `.pbtn.danger` | 文字 `#ff8080`・枠 `#4a2020` | 取消・削除。**確認を挟む** |

- 角丸は **6px**（丸ピルは選択系のみ 999px）
- 押せないときは `disabled` を付ける（`opacity: .35`）。見た目だけ変えて押せる状態にしない
- **1画面に白ボタンは1つまで。** 迷ったら `.btn-sub`

**タブ**は `.tabs > .tab`（`.is-active` で選択）。カードの中の切替は必ずこれを使う。
**択一の見方**（BSの3つなど）は丸ピルの群にする——タブは「同じものの別断面」、
ピルは「同じ数字の別の集計方法」という使い分け。

## 6. 表

- `<table>` は幅100%・行の下線 `#1e1e1e`・セル `padding: .85rem .7rem`
- 見出しは `<thead>` に入れる（`thead th` の書式が自動で当たる）
- **横に長い表は必ず** `<div style="overflow-x:auto">` で包む。ページ全体を横スクロールさせない
- 行をクリックさせるときは `class="row-click"` を付けるだけ。
  キーボード操作（tabindex・Enter/Space）は os-core が自動で面倒を見る
- 空のときは `<td colspan="…" class="dim">—</td>`。「データがありません」と長文で書かない
- 金額列は右寄せ＋等幅数字。前年比などの符号は `+`/`−` を明示

## 7. カードの作法（見た目以外で揃えるもの）

1. **正本は Firestore、画面は表示だけ。** 画面で計算した数字を保存しない
2. **HTMLに実在の金額・係数を書かない**（CIが機械検査）。例え話は「例:」を付ける
3. データの流れは `cachePaint` → `api()` → 内容が変わったときだけ `render()`
4. 認証は `initAuthUI()` を1回呼ぶだけ。個別に signIn/signOut を書かない
5. 状態は URL に載せる（`?tab=` `?prop=` `?view=`）。貼れば同じ画面が再現できること
6. 300行を超えるスクリプトは `<card>.js` に分離する（型検査に載せるため）

## 8. モバイル（〜700px）

- ホームは**ロゴ＋AI質問窓だけ**。表・カード一覧・ハンバーガーは出さない
- 入力欄は **16px 以上**（iOSが自動ズームして画面が壊れる）
- 表は横スクロール、KPIは2列に折り返す
- 固定要素（バナー・入力欄）は `env(safe-area-inset-bottom)` を見込む

## 9. 直すべき既知のズレ（この文書の宿題）

| 内容 | 対処 |
|---|---|
| カード独自 `<style>` が properties 69行・maintenance 47行・reports 41行 | 共通化できるものは os.css へ |
| 囲みの背景が `#101418`（新しいカード）と `#141414`（古いカード）で割れている | `#101418`＋枠 `#1e2630` に寄せる |

新しいカードを作るときは、**まず既存のカードを1枚コピーして始める**（BS・観光客数が最新の作法）。
