## 1. 骨格（枠の位置）

全カードが同じ骨格を持つ。**この順序と余白を崩さない。**

| 部位 | 値 | 備考 |
|---|---|---|
| トップバー | 高さ 49px・`padding: 0.9rem 1.5rem`・下線 `#1c1c1c` | 固定（sticky）。半透明＋ぼかし |
| 左ナビ（os-nav） | 幅 210px | 全ページ共通・`os-nav.js` が描く。カード側で書かない |
| 中央（.main） | `padding: 1.75rem 1.75rem 4rem` | 本文。最大幅はカードの性格で決める（下記） |
| 項目パネル（.aside） | 既定 260px・**sticky** | 左ナビの右。`.layout` に `has-aside` を付けたページだけ出る。中には `.panel2` を積む |
| 右パネル（.panel） | **既定 500px**・可変・**sticky** | 詳細の表示。**空でも隠さず**、`.panel-empty` で「◯◯を選択すると…」と出す——枠が消えると本文の幅が動いて画面が揺れるため |
| 中央上部のタブ帯（.main-tabs） | 最低 2.6rem・**sticky** | **常設**（中身が無くても高さを保ち、ページ間でタブ位置を揃える）。縦にスクロールしてもタブが残る |
| 3ペインの並び | `210px / 1fr / 5px / 500px` | 5px は幅を変えるつまみ |
| 4ペイン（項目パネルあり） | `210px / 260px / 1fr / 5px / 500px` | `.layout.has-aside` |

**帯の高さは共通の `--head-h`（3.4rem）。** 中央のタブ帯（`.main-tabs` / `.prop-head`）と
右パネルの見出し（`.panel-head`）は同じ高さにし、**下線が一本の線に見えるようにする**。
中央の帯は `.main` の上 padding 分だけ上へ引き上げて、トップバー直下の同じ位置から始める。
右パネルの見出しも sticky（パネルの中で `top: 0`）——中央だけ固定で右が流れると段違いになる。

**3つの縦パネル（項目パネル・右パネル・タブ帯）はすべて `position: sticky; top: 49px`。**
本文だけがスクロールし、周りの枠は動かない——これが yah.OS の基本の挙動。

**折りたたみ:** 1400px以下で項目パネルを隠す／1100px以下で右パネルを隠す／900px以下で左ナビも隠す／700px以下はモバイル。

**本文の最大幅**は3種類しかない。増やさない。
- 表が主役（物件・メンテナンス・定期レポート）… 制限なし（3ペインいっぱい）
- 図と数字（BS・観光客数）… `max-width: 980px`
- 読み物（マニュアル・SSoTマップ）… `max-width: 860px`

## 2. タイトルの位置

**画面の題名はトップバーのパンくずが担う。** 本文の見出しはその下。

```html
<nav class="topbar"><div class="topbar-in">
  <span class="crumb"><a href="index.html">yah.OS</a> / 財務 / <b>BS</b></span>
  <span style="margin-left:auto">…状態表示…ログインアイコン…</span>
</div></nav>
<main class="main">
  <!-- 題名はパンくずが担う。h1 は省略してよい -->
  <div class="main-tabs"><div class="tabs">…</div></div>
```

- パンくずは `yah.OS / カテゴリ / <b>カード名</b>`。カテゴリ名は左ナビの見出しと同じ語を使う
- **`<h1>` は省略してよい**（2026-09-01 発注者指示）。パンくずと同じ語をもう一度書くだけになるなら置かない。
  省略したときは、タブ帯が本文の先頭になる。置く場合は **1.05rem**（大きくしない）。
  カード内の節見出しは `<h2>` 0.9rem
- **h1 の直下に「正本はどこか」を1行**書く（`class="note"`）。これはyah.OSの作法——
  画面が正本ではないことを毎回明示する
- 右端は `live-state`（件数・時点）→ ログインアイコンの順。この並びを変えない

## 3. 文字

| 用途 | サイズ | 色 |
|---|---|---|
| 基準（html） | **17px** | — |
| 本文・表 | 0.85rem | `#fff` |
| 表の見出し（thead th） | 0.72rem・字間 0.15em | `#8a8a8a` |
| 補足（.note / .dim） | 0.78rem / — | `#9a9a9a` |
| タグ（.pill） | 0.7rem | `#bbb`・枠 `#333` |
| **下限** | **0.72rem** | これ未満は CI が落とす |

- 書体は **National 2 → 游ゴシック → Hiragino → Noto**（本体サイトと同一の並び・自ホスト）。
  **これ以外のWebフォントを足さない**
- 数字が縦に並ぶ列は `font-variant-numeric: tabular-nums` と `text-align: right`
- 金額は `yen()` / `man()` を使う。カードごとに書式が違うため**あえて共通化していない**——
  それぞれの流儀を守る

## 4. 色

**値はトークン（CSS変数）で持つ。** os.css の先頭 `:root` が色・角丸・行高の正本で、
カードは `var(--panel)` のように**参照だけ**する。生の hex を新しく書かない——
値を直接書くから黄系が4種類に割れた（§9）。守られているかは designcheck が
**ファイル別の生hex件数をラチェット**で数える（金額焼き込みと同じ方式・増えたらCIが落ちる）。

| トークン | 値 | 意味 |
|---|---|---|
| `--bg` | `#000` | 画面の地 |
| `--line-1` / `--line-2` / `--row-line` | `#1c1c1c` / `#262626` / `#1a212a` | 構造／部品／表の行 |
| `--panel` / `--panel-line` / `--panel-head` | `#101418` / `#1e2630` / `#161b21` | 浮いた面／枠／見出し帯 |
| `--ink` / `--ink-2` / `--ink-3` | `#fff` / `#9a9a9a` / `#7d8894` | 本文／補足／薄補足 |
| `--ok` / `--warn` / `--hold` / `--accent` | `#63d297` / `#ef4444` / `#e0b050` / `#6ea8fe` | 機能色（§4の表と同一） |
| `--r-s` / `--r-m` | 6px / 10px | 角丸は2段階＋ピル999px |
| `--row-h` | 2.75rem | 明細1行の高さ（§6.5） |

**背景と枠**（この4つ以外の暗色を新しく作らない）

| 用途 | 値 |
|---|---|
| 画面の地 | `#000000`（ブランドの Black） |
| 区切り線・枠 | `#1c1c1c`（構造）／`#262626`（部品）／`#1e1e1e`（表の行） |
| 沈んだ面（入力欄・タブ） | `#141414` / `#1a1a1a` |
| 浮いた面（囲み・パネル） | `#101418`（枠 `#1e2630`）＝ **`.panel2` が正本**。各カードで再定義しない |

**意味を持つ色**（装飾に使わない。意味が変わるので流用しない）

| 意味 | 値 | 使う場所 |
|---|---|---|
| 正常・増加 | `#63d297` | 状態ドット緑系・前年比プラス |
| 要対応・減少 | `#ef4444`（文中は `#ff8080`） | 警告ドット・前年比マイナス |
| 注意・保留 | `#e0b050` | 印（⚑）・注記の帯 |
| 選択・強調 | `#6ea8fe` | フォーカス枠・選択中・グラフ1本目 |
| 決定ボタン | 背景 `#fff` / 文字 `#0a0a0a` | 「聞く」など主要動作 |

**状態ドット（左ナビ）**は例外的に青＝正常。`d-ok #3b82f6` / `d-warn #ef4444` / `d-na #333`。
**health から導出**し、手動の上書きは人の判断として保存する。

> **既知のばらつき（直す対象）**: 黄系が `#e0a13a`(11) `#e0a355`(12) `#e8c268`(8) `#e0b050`(2) と
> 4種類に割れている。新規は **`#e0b050`** に寄せ、触るついでに既存も置き換える。

## 5. ボタン

**種類は3つだけ。** 新しい見た目を作らない。

| 種類 | クラス | 見た目 | 使いどころ |
|---|---|---|---|
| 副操作 | `.btn-sub` | 透明・枠 `#333`・文字 `#ddd`・0.78rem | 表の行内、パネル内の操作（最も多い） |
| 主操作 | 背景 `#fff`・文字 `#0a0a0a`・太字 | 白ボタン | 画面にひとつ（送信・実行） |
| 危険 | `.pbtn.danger` | 文字 `#ff8080`・枠 `#4a2020` | 取消・削除。**確認を挟む** |

- 角丸は **6px**（丸ピルは選択系のみ 999px）
- 押せないときは `disabled` を付ける（`opacity: .35`）。見た目だけ変えて押せる状態にしない
- **1画面に白ボタンは1つまで。** 迷ったら `.btn-sub`

### タブ（`.tabs > .tab`）

**下線タブ。箱を描かない。**（2026-09-01 発注者決定）
タブ帯は sticky で**常に見えている**ので、軽い見た目にする——箱の枠線は表の罫線と競合する。

| 状態 | 文字 | 下線 |
|---|---|---|
| 通常 | `#9a9a9a` | なし |
| カーソルを乗せる | `#cfcfcf` | なし |
| **選択中**（`.is-active`） | `#ffffff` | **2px `#ffffff`** |
| 押せない（`disabled`） | `#9a9a9a`・不透明度 35% | なし |

- 文字 **0.85rem**・余白 `.5rem .9rem`。下線はタブ帯の下線と重ねる（`margin-bottom: -1px`）
- **折り返さない。** `flex-wrap: nowrap` ＋ 横スクロール（スクロールバーは隠す）。
  固定帯で折り返すと帯の高さが変わり、本文が上下に動く

**棟の切替**（properties / reports / maintenance の上段）も同じ形（`.prop-head > .prop-tab`）。
定義は os.css にひとつだけ。**カード側で `*-tab` を作り直さない**——3枚が各自で定義した結果、
下線が青のまま取り残されていた（2026-09-01 発注者指摘）。

**件数バッジ**（`<span class="tab-n">`）は、**数が意味を持つタブだけ**に付ける。
「受信箱 3」のように、開く前に片付ける量が分かる場合。全タブに付けて 0 を並べない。
要対応の数は `.tab-n.warn`（黄 `#e0b050` 系）にできる。

**択一の見方**（BSの3つなど）は丸ピルの群にする——タブは「同じものの別断面」、
ピルは「同じ数字の別の集計方法」という使い分け。

## 5.5 共通部品（os-core が描く操作部）

- **比較スイッチ（`.scenario-sw`）**: 「現状【…整理前】/ …整理後」のように、実在の数字と
  案の数字を切り替えるピル。**琥珀**（`on` の背景 `#6b5320`・文字 `#f3e2b8`・枠 `#3a2f1e`）——
  主体スイッチの青と同じ色にすると2つの軸が見分けられないため。効かないビューでは
  `.is-off`（灰色・押せない）にし、押しても無反応の状態を作らない
- **用語ツールチップ（`th.has-term`）**: 用語マスタ（Firestore `terms`）に載っている表の見出しは
  点線の下線（`1px dotted #4a5866`）。カーソルを置くと正式名・定義・算式が出る。**カーソル形状は変えない**（？マークは出さない・2026-09-06 発注者指示）——説明がある印は点線だけ
- **説明のホバー（`.has-note`）**: 行の下に添えていた説明のサブコピー
  （「annuity・毎月 ¥151,765・残高（…）」の類）は**行内に出さず、ラベルのホバーに畳む**
  （2026-09-06 発注者決定）。書き方は `data-note="…"`——CSSの `::after` が**即時**表示する。
  ブラウザ標準の `title` は表示まで約1秒かかるので**使わない**。
  `tabindex="0"` と `aria-label` を必ず添える（キーボード・読み上げにも説明を届ける）。
  点線の下線＝「説明がある」の共通の印（th.has-term と同じ文法）。
  **注記の規律（§7.1）との関係**: これは①出典②前提をさらに畳む手段。**③警告は畳まない**
  ——バッジで行の隣に残す決まりは変わらない
- どちらも**見た目の正本は os.css**。os-core.js はクラスを付けるだけでスタイルを注入しない
  （2026-09-04、暫定でJS注入していたのを移設した）

## 6. 表

- `<table>` は幅100%・行の下線 `#1e1e1e`・セル `padding: .85rem .7rem`
- 見出しは `<thead>` に入れる（`thead th` の書式が自動で当たる）
- **横に長い表は必ず** `<div style="overflow-x:auto">` で包む。ページ全体を横スクロールさせない
- 行をクリックさせるときは `class="row-click"` を付けるだけ。
  キーボード操作（tabindex・Enter/Space）は os-core が自動で面倒を見る
- 空のときは `<td colspan="…" class="dim">—</td>`。「データがありません」と長文で書かない
- 金額列は右寄せ＋等幅数字。前年比などの符号は `+`/`−` を明示

## 6.5 縦のリズム（行そろえ）

**横に並ぶパネルの行は、同じ水平線に載せる**（2026-09-06 発注者指示
「縦の行の高さや位置が合ってないのが本当に見づらい」）。

- 明細1行（`.ln`）・合計行（`.tot`）・グループ小見出し（`.grp-h`）は
  **高さ `--row-h`（2.75rem）に固定**。padding で高さを作らない
- 説明はホバー（`.has-note`）に畳んであるので全行が1行で収まる。
  長いラベルは**省略記号**で切る（全文はホバーが持っている）——行を折り返させない
- **見出し帯（`.bs-panel h3` / `.stack-h`）は高さ 3.2rem 固定**。タグや補足は
  下に積まず**右横**に置く（積むと帯が高くなり、隣の列と行がずれる）
- 小見出しを持たないパネルが、小見出しを持つパネルと横に並ぶときは、
  **小見出しぶんの余白を確保**して1行目を揃える（`.headless`）——
  貸借対照表の左右対応そのもの
- **合計行も向かい合わせに。** 列の長さが違うときは、短い列のパネルを列の高さまで伸ばし、
  合計を最下段へ押し下げる（`margin-top: auto`）——資産合計と純資産（結論行）が
  同じ水平線に載る。貸借対照表の左右対応そのもの
- グループ小見出し（`.grp-h`）: 0.72rem・字間 0.15em（表見出しと同じ級数）。
  **グループ分けは台帳の事実で行う**（例: 返済表を持つ借入か）。文字の焼き込みで判定しない

## 6.6 状態と動き

- **押せるもの**（ボタン・タブ・row-click）すべてに
  `transition: background .12s, color .12s, border-color .12s`。**120ms・ease のみ**。
  スライド・バウンス等の演出は入れない（運用画面の品位）
- `prefers-reduced-motion: reduce` で transition / animation を全停止する1行を必ず添える
- `focus-visible` は `outline: 2px solid var(--accent); outline-offset: 2px`
- 初回読み込みは**スケルトン**（`.skel`・1.2sの明滅）。「読み込み中…」等の
  文言バリエーションを作らない。ログイン前は文言のまま（スケルトンだと壊れて見える）
- 合計行は**上に太い罫（2px `--line-2`）**・数字 1.05rem。パネル最後の合計
  （その画面の結論）だけ 1.35rem——数字の階層で読み順を作る

### 6.1 表のセルに入れる文言（2026-09-01 発注者指摘「メモが長い」）

**一覧のメモは要約1行。全角40字以内。** 表は**見比べる**ための道具で、読ませるための場所ではない。
40字を超える説明は、行を選んだときの**右パネル**か、原本そのものへ置く。

**書き方**

- **「何が・どうした」だけ。** 経緯・理由・条件は書かない
- **他の列にある情報を繰り返さない。** 区分列に「見積・契約」とあるなら、メモに「見積」と書かない
- **数字は列に出す。** メモの中に金額や面積を埋めない（並べ替え・合計ができなくなる）
- **固有名詞は略さずに1つだけ。** 「住友不動産」まで。契約番号・省令区分まで入れない

| ✗ 長い | ✓ 端的 |
|---|---|
| 「例: 住友不動産。契約番号2N168。省令準耐火構造・長期優良住宅の認定申請中で…」 | 「例: 住友不動産の請負契約書」 |
| 「例: 確定図（2026-08-10）の前の版。概要書・共通仕様つき…」 | 「例: 確定図の前の版」 |

**守らせ方**

- **入力欄に上限を持たせる**（`maxlength` ＋ 残り字数）。書けなくすれば増えない
- 表示側は1行で打ち切る（`.ellip` ＋ `title` に全文）。**打ち切りは対症療法**であって、
  入力の上限とセットで初めて効く
- 既に入っている長いメモは、**`?action=health` の検証項目**として出す（データの話なので
  `designcheck.mjs` では見えない）

## 7. カードの作法（見た目以外で揃えるもの）

1. **正本は Firestore、画面は表示だけ。** 画面で計算した数字を保存しない
2. **HTMLに実在の金額・係数を書かない**（CIが機械検査）。例え話は「例:」を付ける
3. データの流れは `cachePaint` → `api()` → 内容が変わったときだけ `render()`
4. 認証は `initAuthUI()` を1回呼ぶだけ。個別に signIn/signOut を書かない
5. 状態は URL に載せる（`?tab=` `?prop=` `?view=`）。貼れば同じ画面が再現できること
6. 300行を超えるスクリプトは `<card>.js` に分離する（型検査に載せるため）

### 7.1 注記の規律（仕様: `spec_note_discipline_20260901.md`）

**注記は3種類だけ。** ①出典（どの台帳の、いつ時点の数字か）②前提（係数・期間・除外）
③警告（人の対応が要ること）。**「使い方の説明」は書かない**——それは画面の設計が
足りていないサインなので、文章ではなく列名・タブ名・空状態の文言で解決する。

**出典と前提は画面末尾のフッターに集約し、既定で折りたたむ。**

```html
<footer class="note-foot">
  <details><summary>この画面の前提と出典</summary>
    <ul><li>…</li></ul>
  </details>
</footer>
```

- `.note-foot` は `.main` の**最後の要素**・1画面に**1つだけ**・`open` を付けない
- `<summary>` の文言は「この画面の前提と出典」で固定。ページごとに言い換えない
- 1項目 **60字まで**。超える説明は docs 側に書いてリンクする

**警告はフッターへ送らない。** 「原本が未登録」「残高が古い」は畳んだ時点で気づけない。
**行・値の隣にバッジで残す。**

**画面に出たままの注記は `designcheck.mjs` が数える**（現状値のラチェット）。
増やすと CI が落ちる。フッターへ畳めば数から外れるので、**畳む作業がそのまま基準を下げる**。
減らしたら基準表を下げてコミットすること（検査が知らせる）。

## 8. モバイル（〜700px）

- ホームは**ロゴ＋AI質問窓だけ**。表・カード一覧・ハンバーガーは出さない
- 入力欄は **16px 以上**（iOSが自動ズームして画面が壊れる）
- 表は横スクロール、KPIは2列に折り返す
- 固定要素（バナー・入力欄）は `env(safe-area-inset-bottom)` を見込む
