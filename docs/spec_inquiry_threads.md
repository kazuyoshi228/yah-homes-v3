# 仕様書：問い合わせとメッセージの統合（B案・マジックリンク双方向）

作成 2026-08-15 / 状態 **承認待ち** / 対象 yah.homes 直販P1
前提: 予約後のメッセージ（docs/spec_admin_messages.md・稼働中）と同じ体験を、予約前のお客様にも提供する。

## 0. なぜやるか

予約前後で連絡手段が分断しており、運営は2画面＋メールソフトを行き来している。

```
予約後 → My Page メッセージ ←→ /admin/messages（双方向・稼働中）
予約前 → 問い合わせフォーム → /admin/inbox（閲覧のみ）→ 返信は各自のメールソフトから手作業
```

- 運営の返信が Gmail 頼みで、対応履歴がシステムに残らない
- 決済直前の画面が「2〜3営業日以内にご連絡いたします」と案内しており（C-8）、
  ¥38,800 の決済を迷う人が、数時間で返る Airbnb ホストへ流れる
- 予約前のお客様はアカウントを持たないため、My Page 方式をそのまま使えない
  → **署名トークン付きリンク（マジックリンク）** で、ログインなしの会話画面を渡す

## 1. 全体像

```
お客様                                          運営
┌─────────────────┐                ┌──────────────────┐
│ /contact フォーム送信      │                │ /admin/messages           │
│   ↓ 自動返信メール         │                │ ├ 山田様 清川 3/01 (予約)  │
│ 「ご返信はこちらから」       │   Firestore    │ ├ Kim様 高砂 12/30 (予約) │
│   ↓ リンクを開く           │  ←──────→  │ └ 💬 Chen様 (問い合わせ)   │←NEW
│ /inquiry/?t=<署名>         │   リアルタイム   │    ↑ 予約と同じ画面で返信   │
│  ログイン不要の会話画面      │                └──────────────────┘
│ [ 入力 ......... ][送信]   │                     /admin/inbox は廃止
└─────────────────┘
        ↑ 運営が返信するとメール通知（リンク付き）
```

**スレッドの器は予約メッセージと同じ `threads` を使う。** 画面・通知・翻訳・
レート制限の実装をそのまま流用し、「問い合わせ用の別システム」を作らない。

## 2. データ

```
threads/{id}                          ← 既存コレクションに同居
  kind: "inquiry"                     ← NEW。予約スレッドは "booking"（既存は未設定=booking扱い）
  uid: null                           ← アカウントが無い
  guestName / guestEmail / lang
  contactId（元の contacts ドキュメント参照）
  bookingId: null                     ← 後日この方が予約したら紐づける（§8）
  lastMessageAt / lastFrom / lastBody / lastSystem
  unreadForGuest / unreadForHost
  tokenHash                           ← マジックリンクの検証用（トークン本体は保存しない）
  tokenExpiresAt                      ← 最終活動から90日
threads/{id}/messages/{msgId}         ← 予約メッセージと完全に同形
  from: "guest" | "host" / body / translated? / at / author?（host時）/ system?
```

- フォーム送信の1通目は from:"guest" の最初のメッセージとして入る。
  既存の `contacts` への保存は当面併存（移行が終わったら書き込みを止める）。

## 3. マジックリンク

```
トークン = base64url( threadId + "." + HMAC-SHA256(threadId + "." + expires, SECRET) + "." + expires )
URL     = https://yah.homes/inquiry/?t=<トークン>
```

- **SECRET は Secret Manager**（新規 `INQUIRY_LINK_SECRET`）。DBにはトークンの
  SHA-256（tokenHash）だけを置き、DB が読まれてもリンクを再構成できない形にする。
- **有効期限は最終活動から90日**。運営かお客様の送信があるたびに延長する
  （「3ヶ月後に『あの件ですが』と返ってくる」を殺さない）。
- 期限切れ・改ざんは 410 を返し、画面は「このリンクは期限切れです。お手数ですが
  もう一度フォームからご連絡ください」（5言語）。
- **無効化**: /admin/messages のスレッドヘッダーに「リンクを無効化」（ADMIN のみ・
  audit_logs 記録）。tokenHash を消せばリンクは全て死ぬ。誤送信・転送された場合の非常口。
- リンクは**閲覧と返信ができるだけ**。個人情報の編集・予約情報への接続は無い
  （漏れたときの被害は「この会話が読まれる」まで）。

## 4. API（`messagesApi` を拡張。新関数は作らない）

| 操作 | 認証 | 内容 |
|---|---|---|
| `send` / `read`（既存） | Firebase ID トークン | 変更なし（予約スレッド） |
| `send` / `read` + `inquiryToken` | **トークン** | kind=inquiry のスレッドに限り、トークン検証で本人とみなす |

- 文字数 2,000・1分5通のレート制限・翻訳・Beds24 複製の枠組みは共通。
  ただし inquiry スレッドは Beds24 複製を**しない**（予約が無いので送り先が無い）。
- contact 関数はスレッド作成＋トークン発行＋自動返信メールまでを担う。

## 5. お客様側の画面 `/inquiry/`（5言語・新規1ページ）

- My Page のメッセージ会話部を切り出して流用（吹き出し・自動送信カード・入力欄）。
- ヘッダーは「お問い合わせ」＋お名前。ログイン UI は出さない。
- リアルタイム購読はしない（**ポーリング30秒**）。Firestore ルールを匿名に開ける
  必要がなくなり、読み取りも API 経由に統一できる（read アクションが履歴を返す）。
- 新着はメール通知（既存の MSG_NOTIFY_L10N を流用・リンクは /inquiry/?t=…）。

## 6. 運営側 `/admin/messages` の変更

- 一覧に問い合わせスレッドが混ざる。表示は「💬 お名前｜お問い合わせ」
  （予約スレッドは従来どおり棟・日程）。未読の扱いは同じ。
- ヘッダーに「予約を開く」の代わりに「メールアドレス・言語・リンクを無効化（ADMIN）」。
- フィルタ「未読・進行中／すべて」はそのまま効く。
- **/admin/inbox は廃止**し、メニューから外す。過去の contacts はスレッドへ
  一括移行（1回きりのスクリプト・返信履歴は無いので1通目のみ）。

## 7. 文言の変更（C-8 の解消）

| 場所 | 変更後 |
|---|---|
| フォームの自動返信 | 「ご返信は下のリンクからご覧いただけます」＋リンク。**「2〜3営業日」を削除** |
| 決済画面の信頼ブロック | 「ご質問はお問い合わせフォームから。ご返信はリンクでお知らせします」 |
| その他7箇所の「2〜3営業日」 | 「通常24時間以内」へ置換……**するかは Airstar との合意後**。合意前はこの2箇所だけ直す |

## 8. 予約への接続（この統合の効き所）

お客様が後日予約したとき、**同じメールアドレスの inquiry スレッドを検出**して
予約スレッドのヘッダーに「事前のお問い合わせ 💬」リンクを出す（逆も同様）。
「この方、駐車場のこと聞いてた方だ」が返信前に分かる。
自動マージはしない（別人が同じアドレスを使うケースの誤結合が怖い）。リンク表示のみ。

## 9. 受け入れ条件

- [ ] フォーム送信で threads(kind=inquiry) が生まれ、/admin/messages に並ぶ
- [ ] 運営の返信がメールで届き、リンクから**ログインなしで**全文と入力欄が見える
- [ ] お客様の返信が /admin/messages にリアルタイムで出る・通知メールが飛ぶ
- [ ] 改ざんトークン・期限切れは 410。無効化ボタンでリンクが即死ぬ
- [ ] レート制限（1分5通）・2,000字制限が inquiry スレッドにも効く
- [ ] 他人の予約スレッドにトークンで触れない（kind=inquiry 限定の検証）
- [ ] /admin/inbox の旧データが移行され、メニューから消える
- [ ] 自動返信と決済画面から「2〜3営業日」が消える（§7の2箇所）
- [ ] 5言語で動く
