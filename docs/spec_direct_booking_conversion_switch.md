## 1. 【最優先】デモ/プレビュー環境のGAタグ分離

**問題**: デモサイト（`yah-homes--book-demo-*.web.app`）が本番GA4（G-VJ5DDRML79）に送信しており、テスト決済の `purchase` と 404 が本番データに混入している。

**実測**（2026-08-03〜09 の本番GA4）:
- `purchase` 5件・イベント値 **¥196,400**（すべてテスト）
- `Page Not Found` 36表示・24ユーザー（8/6にゼロから突発＝デモ作業開始と一致）
- キーイベント112件のうち5件がテスト

**なぜ危険か**: このまま Google Ads にコンバージョンをインポートすると、入札アルゴリズムが「日本からのテスト操作」を優良コンバージョンとして学習する。

**対応（いずれか）**:
- (推奨) ホスト名が `yah.homes` 以外のときは GA タグを読み込まない
- 開発用の別GA4測定IDを使う
- 応急: GA4管理 → データストリーム → タグ設定 → 内部トラフィックの定義 でデモのホスト名を除外

**完了条件**: デモで予約テストをしても本番GA4に `purchase` が出ないこと。

## 2. 本番決済の疎通テスト（1件）

Ads側を切り替える前に、**本番環境で実際に1件予約**して以下を確認する。

- [ ] GA4 リアルタイムに `purchase` が届く
- [ ] `value` が実際の総額と一致（税・清掃料込み）
- [ ] `transaction_id` が予約IDと一致
- [ ] GA4 の「トラフィック獲得」で、その `purchase` の参照元が `google / cpc` 等に正しく紐づく（`(not set)` になっていないか）
- [ ] 予約レコードに `gclid` が保存されている（広告経由でテストした場合）
- [ ] テスト予約は返金＋GA4側の扱いを決める（下記4）

**これを飛ばすと「CVが1件も計測されていないのに気づかない」事故になる。**

## 3. Google Ads のコンバージョン切替

### 3-1. インポート
Google Ads → 目標 → コンバージョン → 新しいコンバージョンアクション → **インポート** → Google アナリティクス4（GA4）→ `purchase` を選択。

### 3-2. 設定値

| 設定 | 値 | 理由 |
|---|---|---|
| コンバージョン目標 | **購入（主要）** | 入札の最適化対象にする |
| 値 | **GA4の値を使用**（JPY） | 総額ベース。ROASで見られる |
| カウント方法 | **1回** | 1予約=1CV |
| 計測期間（クリック） | 90日 | リードタイム中央値43〜91日に合わせる（30日だと取りこぼす） |
| アトリビューション | データドリブン | 既定 |

### 3-3. 既存CVの降格（重要）
`click_airbnb` / `click_booking_com`（現 `ads_conversion_booking_1` 系）を **「observation only（副次）」に変更**する。

**主要コンバージョンを2種類（手渡し＋購入）にしてはいけない**: 同一ユーザーの1予約が2回カウントされ、CPAが実際の半分に見える。手渡しは引き続き観測指標として週次で追う。

### 3-4. 切替日を記録
定点シート（ads タブ）のMEMO欄に切替日を記入。**この日を境にCPAの定義が変わる**ため、前後比較には必須。

## 4. 【未実装】キャンセル時の refund 送信

**現状の穴**: 管理画面にStripe返金機能はあるが、GA4へ `refund` イベントを送っていない。キャンセルされた予約がコンバージョンとして残り続ける。

**発生頻度**: キャンセルポリシーが「8日前まで無料」のため、必ず発生する。

**対応**: 返金処理時に Measurement Protocol で `refund` を送る（`transaction_id` は元の予約IDと同一）。実装は `sendPurchaseEvent()` と同型で、イベント名と値を変えるだけ。

```
name: "refund",
params: { transaction_id: booking.id, currency: "JPY", value: 返金額 }
```

## 補足: CV値の定義について

現在は**宿泊総額**を value にしている（例: 2泊6名 ¥102,150）。

- 総額のまま: 分かりやすい。ROASで見られる
- 代案: 「OTA手数料の節約分 ≒ 総額×15%」を value にすると、直販の**利益貢献**が直接見える

**推奨は総額のまま**。許容CPAの判断は「1予約あたりOTA手数料 約¥20,000以下なら黒字」という別の物差しで行えばよく、計測をややこしくする必要はない。
