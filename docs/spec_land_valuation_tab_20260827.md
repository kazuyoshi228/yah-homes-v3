## なぜ「金」に置くか

パネル2の金カテゴリーは現在 **投資額／追加投資額／更新計画** の3つ。
どれも「いくら出したか・これから出すか」＝**出ていく金**の話で、**入ってくる側・戻ってくる側が無い**。

土地の評価額をここに置くと、金の4項目が

| 項目 | 見ているもの |
|---|---|
| 投資額 | 立ち上げに出した金 |
| 追加投資額 | 走りながら出した金 |
| 更新計画 | これから出る金 |
| **土地の評価額** | **いま戻ってくる金** |

と揃う。属性タブに埋めると6年分の表が用途地域・接道・ハザードのあいだに紛れ、
「相場を見る」目的で開く動線が消える。

**ナビの「財務 > 土地の評価額」カード（現在リンク先 null）は空のまま残す。**
4棟横断で評価を並べたくなったとき、この棟別タブから値を引く集約ビューとして作る。
いま作ると中身の半分が物件カードの再掲になる。

## 保存するもの / 保存しないもの

**保存する（＝外部の一次データで、導出できない）**

`properties/{id}.landPriceBenchmark` — 2026-08-27 に4棟へ投入済み

```
landPriceBenchmark
├ source   出所（令和7年地価公示 各標準地点の価格推移・福岡市 財政局・URL・取得日・列の意味）
├ point    "中央5－18 大手門三丁目７７番"
├ zoning   "商業（80・400）・準防火"
├ unit     "円/㎡"
├ note     地点を選んだ理由＋標準地1点の限界
├ years[]  { year, price, yoy } × 6年（2020〜2025）
└ alternates[]  参考地点 { point, zoning, note, years[] }
```

投入済みの地点（用途地域が取得地と一致するものを選定）

| 棟 | 標準地 | 用途地域 | 2025年 |
|---|---|---|---:|
| 大手門 | 中央5－18 大手門三丁目77番 | 商業(80・400)・準防火 | ¥1,280,000 |
| 高砂 | 中央5－2 高砂二丁目10号3番2 | 商業(80・400)・準防火 | ¥995,000 |
| 清川 | 中央5－7 清川二丁目4号13番1 | 商業(80・400)・準防火 | ¥872,000 |
| 六本松 | 中央－5 **六本松四丁目61番** | 第一種住居(60・200) | ¥552,000 |

### 主指標の選び方（2026-08-27 発注者判断）

六本松は当初、丁目が一致する `中央－6 谷一丁目293番`（2025 ¥380,000）を主指標にしていたが、
**「谷は六本松と接している良い場所で、ほぼ六本松で見た方が良い」**との判断で
`中央－5 六本松四丁目61番`（2025 ¥552,000・第一種住居60/200で取得地と完全一致）へ差し替えた。

取得単価 ¥728,079/㎡ との比は、**どの標準地を選ぶかで大きく振れる**。

| 標準地 | 用途地域 | 2025年 | 取得単価との比 |
|---|---|---:|---:|
| 谷一丁目293番 | 1住居 60/200 | ¥380,000 | 192% |
| **六本松四丁目61番（主）** | 1住居 60/200 | ¥552,000 | **132%** |
| 草香江二丁目 | 1住居 60/200 | ¥730,000 | 100% |

**192% と 100% では意味がまるで違う。**だから `alternates` に複数地点を並べて持ち、
画面でも主指標だけでなく参考地点を出す。1地点だけ見せると、選び方の恣意が数字に化ける。

大手門も同様に `中央5－14 大手門一丁目90番外`（2025 ¥2,090,000・主要道路側）を alternates に持つ。

**保存しない（＝毎回計算する）**

取得㎡単価／坪単価／公示との比／評価額／含み益。すべて
`acquisitionPrice`・`landArea`・`landPriceBenchmark.years` から導出できる。
保存すると、公示が更新されたときに古い比率が残る。

## 画面（パネル3）

### 1行目 — 結論

```
土地の評価額（公示ベース）        ¥122,278,400
　取得時の土地単価 ¥1,058,306/㎡ ／ 公示2025 ¥1,280,000/㎡ ＝ 83%
```

評価額 ＝ `landArea × 直近年の公示価格`。

### 2. 公示地価の推移

| 年 | 公示(円/㎡) | 変動率 | 取得単価との比 |
|---|---:|---:|---:|
| 2020 | 690,000 | +26.6% | 153% |
| … | | | |
| 2025 | 1,280,000 | +13.3% | **83%** |

「取得単価との比」は取得㎡単価 ÷ その年の公示。
**取得年より前の年は薄く出す**（買う前の相場なので、比較の意味が弱い）。

### 3. 参考地点

主指標の下に `alternates` を折りたたみで並べる（六本松3件・大手門1件）。
**主指標の数字だけを出さない。**選び方で比率が2倍変わることが見えるようにする。

### 4. 3つの見方を並べる

| 見方 | 金額 | 出所 |
|---|---:|---|
| 公示ベース | landArea × 直近公示 | landPriceBenchmark |
| 収益還元（cap 5.0%） | 1Pagerと同じ式 | assumptions/cap-rate |
| 取得原価 | 投資の累計 | items（取得費用）＋台帳 |

**3つ並べるのが要点。**どれか1つを「評価額」と呼ばない。
売るなら公示ベース、回すなら収益還元、税務なら取得原価と、目的で使う数字が変わる。

### 5. 注記（画面に出す）

- 標準地は1地点の評価。接道・幅員・形状・規模で実勢は大きく振れる
- **清川・高砂は土地建物一体で取得**しているため、取得単価との比は建物込みの数字
  （清川108%・高砂94%）。土地建物の按分は未確定で、**別途進める**
  （2026-08-27 発注者判断＝方針A: 按分を待たずに注記で断って出す）
- 大手門は前面道路4mで容積が240%に絞られる（指定は400%）。
  公示比83%はその対価であって値引きではない

## 実装

1. `props.ts` の `PROP_FIELDS` に `"landPriceBenchmark"` を1行追加
   — 現在ホワイトリストに無く、APIが返す前に弾かれるため画面から見えない
2. `properties.html`
   - パネル2の金カテゴリーに `data-t="land"` のボタンを1つ追加（更新計画の下）
   - パネル3に `v-land` ビューを追加（上の5ブロック）
   - 1Pagerに1行だけ足す: `土地（公示ベース） ¥122,278,400（公示2025比 83%）`
3. デプロイ — CI（push to main）

**保存の経路は作らない。** `landPriceBenchmark` は年1回、公示の発表後に
Claude が一次資料（福岡市のPDF）から `years` に1行足す運用。
画面から編集できるようにすると、出所の分からない数字が入る。
