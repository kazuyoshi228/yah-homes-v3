# yah.OS 仕様書 v1.2（2026-08-19 更新・デモ確定状態を反映）

## 1. 目的と読者

- **読者**: プライベートエクイティ（国内・宿泊/不動産系の投資担当）。リンクを直接送る想定。
- **役割**: 「運営が人ではなく仕組みに載っている」ことを1枚で見せるエクイティストーリーの入口。
  プロダクト宣伝ページではない。読ませるのではなく**一覧で構造を掴ませる**。
- **数字は載せない**（v1）。数字の格納先として「財務」カードを器だけ用意し、後から充填する。

## 2. URL・公開設定

| 項目 | 内容 |
|---|---|
| URL | `os.yah.homes`（Firebase プロジェクト yah-homes に hosting site `yah-os` を追加） |
| 検索 | noindex, nofollow（meta + X-Robots-Tag）。サイトマップ・内部リンクなし |
| ゲート | v1 は URL 非公開運用のみ。数字を載せる段階でパスコードゲートを追加（別仕様） |
| 言語 | 日本語のみ。英語版は将来判断 |

## 3. 実装方式

- **新規の極小リポジトリ `yah-os`**（ビルド無し・index.html 1枚＋インラインCSS/SVG）。
  yah.homes-v2 に同居させない理由: あちらのビルドは SSoT 必須で重く、この1枚に不要。
  デプロイは `firebase deploy --only hosting:yah-os`。
- 外部ライブラリ・Webフォント・トラッキングなし。アイコンはすべてインラインSVG（白線画 1.5px）。

## 4. デザイン原則

- **黒背景**（#0a0a0a 前後）・白文字・余白広め・ミニマル（2026-08-18 発注者指示）。
  yah.homes（白基調）とは意図的に反転させ、「お客様向けの宿」と「投資家向けのOS」を面で区別する。
  アイコンは白の線画1.5px、カードは極薄いグレーの面（#141414 程度）＋細い罫線。CTA青は使わない。
- **サブコピー最小**: カードは「**アイコン＋名称のみ**」（一行説明も置かない・2026-08-18 発注者指示）。
  タグラインも置かない（2026-08-19 削除決定）。

### 4-2. 3ペイン構造（2026-08-19 確定・**OSデザインの根幹**）

```
┌────────────────────────────────────────────────────┐
│ MENUバー: yah.OSロックアップ｜ユーザー・☰          │
├────────────────────────────────────────────────────┤
│ BIG KPIストリップ: human-minutes/週・棟 90分 |      │
│ 先付け率 28% | NAV ¥1.9億（当て・事業の肝の三拍子） │
├──────────┬──────────────────────┬────────────────┤
│ 左: MENU │ 中央: カードグリッド │ 右: 詳細パネル │
│ 全てのAgent│ 8カテゴリ29カード   │ **常設**（3列固定）│
│ **稼働中** │ 縦積み（アイコン上・ │ 未選択=空の案内 │
│ 8カテゴリ │ 名称下）＋右上ドット │ 選択で: 管理画面を│
│ 裏方     │                      │ 開く↗・状態・   │
│          │                      │ 自動化レベル・設定│
└──────────┴──────────────────────┴────────────────┘
```

- **BIG KPIストリップ**: 事業の肝（24H/365・サブスク的売上・資本価値）と1対1の3計器。
  本実装では human-minutes=記録シート / 先付け率=先付け泊数÷販売可能泊数（bookings+Beds24）/
  NAV=評価額−残債、をSSoTから自動更新
- **左MENU=フィルタ**: 「全てのAgent」→「**稼働中**（ドットが青のカードのみ横断表示・
  空カテゴリは非表示）」→8カテゴリ→裏方（監査ログ・ヘルス・マニュアル）。受信箱は置かない
- **中央=カード（縦積みで確定）**: アイコン上・名称下・右上ドットのみ。
  Aマーク等のカード面バッジは置かない（試行の結果うるさいため撤去・2026-08-19）。
  カードクリックで右パネルへ（詳細はOS上に複製しない）
- **右パネル=常設**: 3列は常に表示（未選択時は空の案内）。選択カードの
  「管理画面を開く↗」（飛び先のあるカードのみ）・状態（ドット切替と連動）・
  **自動化レベル（AUTO/半自動/人間の表示はここだけ）**・設定/履歴の器
- **状態ドット**: 青=OK/赤=要改善。クリック切替・ブラウザ保存。初期は全赤で
  「確認できたものから青に落とす」巡航チェック運用
- PC幅いっぱい。1100px未満でパネルはオーバーレイ・900px未満で左MENUも畳む

## 6-2. 財務データの置き場所（2026-08-18 発注者と合意）

- 財務数字は **Firestore に置かない**。正本はスプレッドシート（42ヶ月モデル・Cockpit）のまま、
  掲載する段階でページに焼き込む（物件ファクトと同じ「正本1つ＋焼き込み」の思想）。
- 既定DBには置かない（公開読み取り前提の予約DBと守秘水準が違う）。
- **決定（2026-08-19）: 名前付きDB `agency` を新設**し、運営コンソール系データ（業者・ジョブ・点検周期・カード状態・将来の承認キュー）はすべてそこに置く。財務数字は引き続き
  Firestoreに置かない（正本はシートのまま）。プロジェクト分離は外部にIAMを渡す段階で検討。

## 7. カードの振る舞い（確定）

- カードクリック → 右パネルに詳細（管理画面リンク・状態・自動化レベル・設定/履歴の器）。
- カード＝ランチャー。詳細は各システムの管理画面が正本で、OS上に複製しない（OS=LP・ハブ）。
- 初期表示はすべて静的HTMLに焼き込み（JS無し環境でも全体が見える）。JSは操作のみ担当。
