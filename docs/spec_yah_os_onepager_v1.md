# yah.OS 一枚ページ 仕様書 v1（2026-08-18・承認待ち）

## 1. 目的と読者

- **読者**: プライベートエクイティ（国内・宿泊/不動産系の投資担当）。リンクを直接送る想定。
- **役割**: 「運営が人ではなく仕組みに載っている」ことを1枚で見せるエクイティストーリーの入口。
  プロダクト宣伝ページではない。読ませるのではなく**一覧で構造を掴ませる**。
- **数字は載せない**（v1）。数字の格納先として「財務」カードを器だけ用意し、後から充填する。

## 2. URL・公開設定

| 項目 | 内容 |
|---|---|
| URL | `os.yah.homes`（Firebase プロジェクト yah-homes に hosting site `yah-os` を追加） |
| 検索 | noindex, nofollow（meta + X-Robots-Tag）。サイトマップ・内部リンクなし |
| ゲート | v1 は URL 非公開運用のみ。数字を載せる段階でパスコードゲートを追加（別仕様） |
| 言語 | 日本語のみ。英語版は将来判断 |

## 3. 実装方式

- **新規の極小リポジトリ `yah-os`**（ビルド無し・index.html 1枚＋インラインCSS/SVG）。
  yah.homes-v2 に同居させない理由: あちらのビルドは SSoT 必須で重く、この1枚に不要。
  デプロイは `firebase deploy --only hosting:yah-os`。
- 外部ライブラリ・Webフォント・トラッキングなし。アイコンはすべてインラインSVG（白線画 1.5px）。

## 4. デザイン原則

- **黒背景**（#0a0a0a 前後）・白文字・余白広め・ミニマル（2026-08-18 発注者指示）。
  yah.homes（白基調）とは意図的に反転させ、「お客様向けの宿」と「投資家向けのOS」を面で区別する。
  アイコンは白の線画1.5px、カードは極薄いグレーの面（#141414 程度）＋細い罫線。CTA青は使わない。
- **サブコピー最小**: ヒーローに1文だけ。カードは「**アイコン＋名称のみ**」（一行説明も置かない・2026-08-18 発注者指示）。
- 1枚（縦スクロール1画面〜2画面以内・モバイル対応）。

## 6-2. 財務データの置き場所（2026-08-18 発注者と合意）

- 財務数字は **Firestore に置かない**。正本はスプレッドシート（42ヶ月モデル・Cockpit）のまま、
  掲載する段階でページに焼き込む（物件ファクトと同じ「正本1つ＋焼き込み」の思想）。
- 既定DBには置かない（公開読み取り前提の予約DBと守秘水準が違う）。将来どうしてもDBが要る
  用途（PEごとの出し分け・閲覧ログ等）が出たら、chat と同じ型で**名前付きDB `os` を新設**する。
  プロジェクト分離は外部にIAMを渡す段階で初めて検討。

## 7. カードの振る舞い

- v1 はすべて**静的**（クリック無し）。
- ただしHTML構造は「カード＝詳細を持てる器」にしておく（後から財務カードに展開/モーダルで数字を入れられる形）。
