# 設計：レビューページ /review ＋ 管理 /admin/review

作成 2026-08-10 / 状態 **提案（承認待ち）** / 準拠: docs/brand/brand-reference.md

## 1. 何を解くか

- **未決だった `{{reviewUrl}}` の着地先を作る。** 直販のお客様は Airbnb にレビューを書けない。
  チェックアウト翌日のレビュー依頼メールから、自社のレビュー投稿へ誘導する。
- レビューは現在、トップの Pickup Reviews（手書きの抜粋）と OTA の集計値
  （`4.77` などコードに直書き）しかない。**投稿の受け皿・蓄積・管理画面がない。**
- 将来の直販比率が上がるほど、OTAに載らない「声」が消えていく。自社に貯める箱を先に作る。

## 2. ページ構成 /review（公開・5言語）

ブランド文法に沿う: モノクロ4色のみ・National 2 / 游ゴシック・SectionHeading（罫線＋番号＋英字ラベル）・
レビュー本文は**黒地カードの引用**（トップの Pickup Reviews と同じ言語）。

```
─ REVIEWS                                   ← SectionHeading（罫線＋ラベル）
ご滞在の声
実際にご宿泊いただいたお客様の声です。掲載は原文のまま。

┌─────────────────┐ ┌─────────────────┐
│ yah.homes kiyokawa        │ │ yah.homes takasago        │   ← 集計カード（白地・細罫）
│ ★★★★★  4.77            │ │ ★★★★★  4.89            │      OTA＋直販の合算 or 併記
│ 128 reviews ・2026-08時点  │ │ 74 reviews ・2026-08時点   │
└─────────────────┘ └─────────────────┘

[ すべて ] [ kiyokawa ] [ takasago ]        ← フィルタ（黒ピル・言語切替と同じ形）

┏━━━━━━━━━━━━━━━━━━━━━━━┓
┃ ★★★★★                      kiyokawa ┃   ← 黒カード（#111 地・白文字）
┃ 「駅から近く、家族4人でも広々。…」        ┃      引用符で始まる本文
┃ ── Kim ・韓国 ・2026年7月滞在 ・直販     ┃      名前は表示名（イニシャル可）
┗━━━━━━━━━━━━━━━━━━━━━━━┛
┏━━━━━━━━━━━━━━━━━━━━━━━┓
┃ …                                        ┃   ← 縦積み・ページング（12件ずつ）
┗━━━━━━━━━━━━━━━━━━━━━━━┛
```

- **投稿フォームは常設しない。** レビュー依頼メールのリンク（`/review/?t=<トークン>`）で
  開いたときだけ、ページ上部にフォームが差し込まれる。
  誰でも書ける欄を置くと、宿泊していない人の投稿とスパム対策が別途必要になるため。
- フォーム: ★1〜5（タップ）＋ 本文（自由記述）＋ 表示名（本名 / イニシャル / 匿名 から選択）。
  3項目だけ。細分評価（清潔さ等）は設けない（回答負荷を上げると母数が減る）。
- 投稿後: 「ありがとうございました。掲載まで数日いただきます」— **即時掲載しない**（§4）。
- JSON-LD: `AggregateRating` ＋ 各レビューの `Review`（公開分のみ）。
- 一等パス `/review/`（en）・`/{lang}/review/`。ナビの「ローカルガイド」等と同列にはせず、
  フッター＋トップのレビュー節から「すべての声を見る →」で誘導。

## 3. データと投稿の仕組み

```
reviews/{id}（Firestore・直販投稿とOTA転記の両方）
  prop:      "kiyokawa" | "takasago"
  source:    "direct" | "airbnb" | "booking"
  rating:    1–5
  body:      本文（原文のまま・編集しない）
  name:      表示名（お客様が選んだ形）
  country:   任意
  lang:      投稿言語
  stayMonth: "2026-07"
  bookingId: 直販のみ（重複投稿の防止に使う）
  status:    "pending" | "published" | "hidden"
  createdAt / publishedAt / publishedBy
```

- **トークン** = 予約IDのHMAC署名（`reviewApi` が検証）。予約1件につき1回だけ投稿できる
  （投稿時に booking へ `reviewPostedAt` を記録）。チェックアウト後のみ有効。
- `{{reviewUrl}}` の値 = `https://yah.homes/review/?t=<トークン>`（レビュー依頼メールに差し込み）。
  これでレビュー依頼メールの本文に「レビューを書く」ボタンを追加できる。
- 表示は **公開API（published のみ）をクライアント取得**。掲載・非掲載が再デプロイなしで反映される。
  集計値と導入文は静的に焼く（SEOの本体）。個別レビュー本文のSSR焼き込みは P2（§7）。

## 4. 管理 /admin/review

権限: 管理者台帳のメンバー（運営会社を含む）。既存の管理画面と同じログイン・同じ見た目。

```
[ 承認待ち 3 ] [ 掲載中 12 ] [ 非掲載 1 ]      ← ステータスタブ

┌──────────────────────────────┐
│ ★4  kiyokawa ・直販 ・2026-08-09 投稿          │
│ 「とても清潔でした。ただ駐車場が…」             │
│ Kim（表示名: K.）・予約 A1B2C3D4               │
│ [ 掲載する ] [ 非掲載にする ]  メモ [________]  │
└──────────────────────────────┘

── OTA転記の追加 ──────────────
Airbnb・Booking.com のレビューを手で転記する（出典を明記して掲載）
[ 物件 ▾ ][ 出典 ▾ ][ ★ ][ 本文 ][ 表示名 ][ 滞在月 ] [追加]

── 集計値の管理 ──────────────
表のトップ・/review の集計カードに出る数値（OTAの現在値を手で更新）
kiyokawa  評価 [4.77] 件数 [128] 時点 [2026-08]
takasago  評価 [4.89] 件数 [ 74] 時点 [2026-08]   [保存]
```

- **掲載は人間だけが行う**（鉄則1と同じ思想。システムは pending 止まり）。
- 本文は編集不可。**掲載するか、しないかの二択**（お客様の言葉を書き換えない）。
  個人情報や誹謗が含まれる場合は非掲載にし、メモに理由を残す。
- 集計値は `property_facts` に `rating / reviewCount / ratingAsOf` として保存
  （現在コード直書きの `4.77` を移す）。次回ビルドでトップにも反映。
- 全操作 `audit_logs` に記録。

## 5. 実装物

| 種別 | 内容 |
|---|---|
| Functions | `reviewApi`（トークン検証・投稿受付・公開一覧）、`adminReviews`（審査・OTA転記・集計値） |
| ページ | `/[locale]/review`（5言語）、`/admin/review` |
| 変更 | レビュー依頼メールに「レビューを書く」ボタン（`{{reviewUrl}}`）、`property_facts` に集計3項目、Pickup Reviews のデータ源を段階的に Firestore へ |

## 6. 受け入れ条件

- [ ] レビュー依頼メールのリンクからのみ投稿できる（トークンなしはフォーム非表示）
- [ ] 1予約1回・チェックアウト後のみ
- [ ] 投稿は pending。管理画面で人間が掲載して初めて /review に出る
- [ ] 掲載・非掲載が再デプロイなしで反映される
- [ ] 本文は管理画面から編集できない
- [ ] 集計値を管理画面で更新でき、次回ビルドでトップに反映される
- [ ] 5言語・モノクロ4色のみ・黒カード引用のブランド文法

## 7. 未決・P2

- 個別レビュー本文のSSR焼き込み（SEO強化。P1はクライアント取得＋静的集計で開始）
- 低評価（★1–2）投稿時のオーナー即時通知メール
- 返信（オーナーからのコメント）表示
- Pickup Reviews（トップ）の完全Firestore化
