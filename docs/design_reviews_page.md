# 設計：レビューページ /review ＋ 管理 /admin/review（v2）

作成 2026-08-10 / 状態 **提案（承認待ち）** / 準拠: docs/brand/brand-reference.md

## 0. v1からの変更（発注者前提）

- **直販サイトで集めたレビューは掲載しない。裏でデータとして保管する。**
  → 公開ページに載るのは OTA のレビュー（出典明記の転記）と集計値のみ。
  直販の投稿は非公開のフィードバックとして /admin/review でだけ読める。
  掲載審査・公開フローは丸ごと不要になり、設計が大幅に軽くなる。
- **集計値の管理は新設しない。** property_facts に rating / reviewCount / ratingAsOf が既にあり、
  /admin/properties に編集欄も既にある。やるのは読み先の統一だけ（§5）。

## 1. 何を解くか

- 未決だった `{{reviewUrl}}` の着地先。直販のお客様は Airbnb にレビューを書けないため、
  チェックアウト翌日のメールから**自社の非公開フィードバック**へ誘導する。
- 声の資産化: OTA に散らばるレビューを 1 ページに集約して見せる（/review）。
- 直販の生の声を、公開プレッシャーなしで集めて蓄積する（改善材料・将来の資産）。

## 2. 公開ページ /review（5言語）

モノクロ4色・National 2 / 游ゴシック・SectionHeading・黒地カードの引用（Pickup Reviews と同じ文法）。

```
─ REVIEWS
ご滞在の声
Airbnb・Booking.com にお寄せいただいた声を、原文のまま掲載しています。

┌ yah.homes kiyokawa ─┐ ┌ yah.homes takasago ─┐
│ ★★★★★  4.77         │ │ ★★★★★  4.67         │  ← property_facts から（既存の管理で更新）
│ 47 reviews ・2026-08   │ │ 36 reviews ・2026-08   │
└────────────┘ └────────────┘

[ すべて ] [ kiyokawa ] [ takasago ]

┏━━━━━━━━━━━━━━━━━━━━━┓
┃ ★★★★★                    kiyokawa ┃  ← 黒カード（#111地・白文字）
┃ 「駅から近く、家族4人でも広々。…」      ┃
┃ ── Kim ・韓国 ・2026年7月滞在 ・Airbnb ┃  ← 出典を必ず明記
┗━━━━━━━━━━━━━━━━━━━━━┛
```

- 掲載されるのは source が airbnb / booking のもののみ（管理画面から転記）。
- 表示はクライアント取得（公開API・published のみ）。転記の追加・取り下げが再デプロイなしで反映。
- JSON-LD `AggregateRating`（集計はビルド時に property_facts から焼く）。
- 導線: フッター＋トップのレビュー節に「すべての声を見る →」。

## 3. 直販フィードバック（非公開）

- `{{reviewUrl}}` = `https://yah.homes/review/?t=<トークン>`。
  トークン付きで開いたときだけ、ページ上部にフォームが差し込まれる（常設しない）。
- トークン = 予約IDのHMAC署名。チェックアウト後のみ有効・1予約1回（booking に reviewPostedAt）。
- フォーム3項目: ★1〜5 ／ 本文 ／ お名前の扱い（そのまま・イニシャル・匿名）。
  文言で明示する: **「いただいた内容は公開されません。今後の改善のためにのみ使用します」**。
  公開されないからこそ率直に書ける、を価値にする。
- 送信後: お礼画面。★4以上のときだけ「よろしければ Airbnb にも」と OTA レビューへの
  リンクを添える（OTA予約者の場合のみ表示・レビュー誘導は自然な範囲に留める）。
  ※直販のお客様は Airbnb に書けないため、直販予約ではこの誘導は出さない。

```
reviews/{id}（Firestore）
  prop / source: "direct" | "airbnb" | "booking" / rating 1-5 / body / name / country?
  lang / stayMonth / bookingId?（directのみ）
  visibility: "private"（direct固定） | "published" | "hidden"（OTA転記）
  createdAt / createdBy（転記時は管理者メール）
```

## 4. 管理 /admin/review

権限: 管理者台帳のメンバー。全操作 audit_logs。

```
[ 直販フィードバック 8 ] [ OTA転記 12 ]

── 直販フィードバック（非公開・閲覧のみ）──
┌────────────────────────────┐
│ ★2  takasago ・2026-08-09 ・予約 A1B2C3D4    │  ← ★2以下は上に・目立たせる
│ 「シャワーの水圧が…」 田中（イニシャル希望）     │
│ 対応メモ [________________] [保存]             │
└────────────────────────────┘
平均 ★4.6（8件）・低評価 2件               ← 数値のサマリ

── OTA転記 ──
[ 物件 ▾ ][ 出典 ▾ ][ ★ ][ 本文 ][ 表示名 ][ 国 ][ 滞在月 ] [追加]
掲載中リスト … [取り下げ]
```

- 直販フィードバックは**閲覧と対応メモのみ**。編集・公開の操作は存在しない（前提どおり）。
- 低評価（★1–2）が届いたら通知メール（notifyBookings の宛先へ）。
  非公開だからこそ、不満はレビューサイトではなくここに先に届く＝**火消しの早期警報**になる。
- OTA転記は管理者が入れるものなので審査不要。追加＝掲載、取り下げ＝非表示の二操作だけ。
- 集計値（4.77等）はここでは扱わない。/admin/properties の既存欄へリンクを置くだけ。

## 5. あわせて直す（読み先の統一）

- OurReviewSection（トップのレビュー節）の評価・件数を data/properties.ts から
  **property_facts（getPropertyFacts）へ切り替える**。/admin/properties での更新が
  物件カードとレビュー節の両方に効くようになる。
- kiyokawaData.ts / takasagoData.ts / data/properties.ts に残る "4.77" 等の直書きコピーを
  facts 参照に置換（不整合の温床を消す）。

## 6. 実装物

| 種別 | 内容 |
|---|---|
| Functions | `reviewApi`（トークン検証・直販投稿受付・OTA転記の公開一覧）、`adminReviews`（閲覧・メモ・転記・取り下げ・低評価通知） |
| ページ | `/[locale]/review`（5言語）、`/admin/review` |
| 変更 | レビュー依頼メールに「感想を送る」ボタン（{{reviewUrl}}・5言語）、読み先の統一（§5） |

## 7. 受け入れ条件

- [ ] 直販の投稿は visibility=private 固定で、/review にもAPIにも一切出ない
- [ ] トークンなしでフォームは出ない・1予約1回・チェックアウト後のみ
- [ ] フォームに「公開されません」の明示（5言語）
- [ ] ★1–2 の投稿で通知メールが飛ぶ
- [ ] OTA転記の追加・取り下げが再デプロイなしで /review に反映
- [ ] /admin/properties で評価を変えると、次回ビルドでトップのレビュー節にも反映される
- [ ] モノクロ4色のみ・黒カード引用・出典明記

## 8. P2

- 直販フィードバックのCSV書き出し／月次サマリ（定点観測メールへの同梱）
- 満足ゲスト（★5）への Google クチコミ誘導の検討
