## A. 売上レポートの自動取込（価値◎・毎月の手作業が消える）

AIRSTARの月次報告PDFはメールで届く。Gmail委任の受信基盤（dispatcher の inbox）は**もう動いている**。

```
受信 → 報告PDFを検知 → 数字を抽出 → 検算（支出=B+C+D・入金=売上−支出。過去23/23通過の式）
  → 合格: revenue に「未検収」行＋PDFを保管庫へ＋healthに「未検収の月次報告あり」
  → 不合格: 取り込まず警報（壊れた数字を黙って入れない）
人: 定期レポートで1クリック検収 → 確定
```

- 工数: 1日／毎月の効果: PDF転記・保管・検算の全手作業がゼロに

## B. 契約期限 → ジョブ自動起票（小・即効）

contracts の `expiresAt`／`noticeDays` から、期限の手前で「更新可否の判断」ジョブを毎朝自動起票。
いまは契約ごとに schedules を手で作っている（Airstar分だけ存在）——**契約を登録すれば見張りが付いてくる**形に。

- 工数: 2時間。12/31のAirstar判断のような期限が、登録漏れなく毎回ジョブになる

## C. 見積の催促 → ジョブ化（小）

「概算のまま実施年が近い」は毎朝のメールに載るだけ。これを **draft ジョブ「見積を取る」** として起票し、
今日ボード・メンテナンスの待ち行列に出す。メールは読み流せるが、ジョブは消し込むまで残る。

- 工数: 1時間

## D. 仕訳CSVのドロップ取込（毎月の光熱費・備品の入口）

MoneyForwardの仕訳CSVを保管庫の `inbox/` に置くだけで:
分類ルール（今の type/place 判定をコード化済み）で utilities 行を下書き → txNo血統チェック → health に「未検収の仕訳 n行」。

- 工数: 半日。「CSVを置く」以外の手作業が消える

## E. スクショ受信箱＋自動読取（創造枠・CVR定点の入口）

CVRスクショは毎月LINEで届く。2段で:
1. **第1段（すぐ）**: 保管庫 `reports/cvr/inbox/` に画像を置くと、Geminiで数値を読取り→
   **検算（閲覧÷表示＝検索→閲覧）に合格した行だけ** cvr に「未検収」で下書き。今回手でやった作業の自動化
2. 第2段（任意）: LINE Messaging API のボットが受信して inbox へ自動保存——「転送すら不要」

- 工数: 第1段 半日／第2段 1日。読取りの検算ゲートがあるので誤読は構造的に入らない

## F. 朝のダイジェスト統合（今日ボードのメール版）

外部委託の点検メールを **health全体のダイジェスト**に拡張（今日ボードと同一ソース）。
画面とメールが同じ景色になる。異常がある日だけ届く原則は維持。

- 工数: 2時間

## G. 事業承継スコアの自動ドラフト（創造枠）

採点8観点のうち測定可能なもの（契約=原本未登録数・SSoT=health警告数・記録=定点の継続日数…）を
四半期ごとに自動計算し、**「前回 78.1 → 提案 79.4（根拠つき）」の下書き**を作る。人は直して保存するだけ。
判断は人のまま、集計だけ機械へ。

- 工数: 半日

## H. 保証期限ウォッチ（小）

設備台帳の保証（エアコン10年・TV5年…）に `warrantyUntil` を持たせ、切れる90日前に health へ。
「保証が生きているうちに修理に出す」を仕組みにする。

- 工数: 2時間＋既存データの年限入力30分
