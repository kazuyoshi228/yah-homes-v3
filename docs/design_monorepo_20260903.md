## 統合後の構成

```
yah-homes/                        ← 新リポ（または yah.homes-v2 を母体に）
  apps/
    web/                          ← 旧 yah.homes-v2 のフロント（Astro）
    os/                           ← 旧 yah-os（静的HTML・カード33枚）
    chat/                         ← 旧 chat-yah-homes-v1
  functions/
    src/
      agency/                     ← yah.OS のサーバー（45ファイル・derive.ts はここ）
      chat/                       ← chat の関数（codebase: chat）
      ...                         ← 宿泊サイト本体（10ファイル）
  tools/                          ← BigQuery・検査など横断のもの
  docs/                           ← 設計書・指示書
  firebase.json                   ← hosting 3サイト＋functions 2 codebase を1つに
  CLAUDE.md                       ← 1本に統合
```

**`derive.ts` が `apps/os` から相対パスで見える**ようになる。これが最大の目的。

## 山場: `deploy.sh` の門番

**いちばん効いている安全装置を、弱くしてはいけない。**

いまの yah-os の `deploy.sh` は「ツリーが clean かつ origin/main と一致していないと止まる」。
CLAUDE.md にこうある:

> これは**別スレッドの書きかけファイルが本番に混入するのを防ぐ門番**。壊さない・迂回しない

**1リポにすると、chat の書きかけが yah.OS のデプロイを止める。**
並行作業が日常なので（この日も v2 に別スレッドの未コミットが2件あった）、毎日起きる。

### 対策案

**案1: 変更範囲で判定する（推奨）**
```sh
# apps/os を出すときは、apps/os 配下だけが clean であればよい
git status --porcelain -- apps/os functions/src/agency | grep . && exit 1
```
- 利点: 仕組みが単純。いまの門番の思想を保てる
- 注意: `functions/src/agency` も見る必要がある（カードとエンドポイントは対）

**案2: git worktree を分ける**
- 利点: 物理的に混ざらない
- 欠点: 運用が重い。統合の目的（すっきりさせる）に反する

**案1で行く。** ただし**「どのディレクトリがどのデプロイに属するか」の対応表**を
`deploy.sh` の中に明示し、増えたときに直し忘れないようにする。

## CI を分ける

いま合計7本。統合すると、1文字直すたびに全部回る。

GitHub Actions の `paths:` フィルタで分ける。

```yaml
on:
  push:
    paths: ['apps/os/**', 'functions/src/agency/**']
```

| ワークフロー | 監視するパス |
|---|---|
| os のゲート4本 | `apps/os/**`, `functions/src/agency/**` |
| web のデプロイ | `apps/web/**` |
| functions のデプロイ | `functions/**` |
| chat のCI | `apps/chat/**`, `functions/src/chat/**` |

**検査スクリプトの相対パスを直す必要がある**（`typecheck.mjs` などは
カレントディレクトリ基準で書かれている）。

## 移行手順

各段階で切り戻せること。**1〜3は本番に触れない。**

| 段階 | 内容 | 所要 | 本番停止 | 切り戻し |
|---|---|---|---|---|
| 1 | 新リポを作り、`git subtree add` で3つを取り込む（履歴を保つ） | 半日 | なし | 新リポを捨てる |
| 2 | CI を `paths:` で分け、全ゲートが通ることを確認 | 半日 | なし | 同上 |
| 3 | `deploy.sh` の門番を作り直し、`--preview` で検証 | 半日〜1日 | なし | 同上 |
| 4 | `firebase.json` を統合し、**プレビューチャンネルで3サイト全部を出す** | 半日 | **山場** | 旧リポからデプロイし直す |
| 5 | 本番デプロイを新リポに切り替え。旧3リポは読み取り専用に凍結 | 半日 | あり | 旧リポを解凍して戻す |

**段階4で必ずプレビューを通すこと。** 3サイト同時に出して、
os.yah.homes・yah.homes・chat.yah.homes のすべてが動くことを確認してから5へ進む。
