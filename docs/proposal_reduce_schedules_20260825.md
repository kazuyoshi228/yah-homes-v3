## 1. 提案A — 設備台帳由来の19件を schedules から外す（最大の削減）

`ledgerId` を持つ19件は、**周期も金額も設備台帳（equipment）が正本**で、
schedules 側は「いつ起票するか」の器としてしか存在していない。
しかも更新計画・更新カレンダーに**同じものが既に出ている**。

### やり方

schedules から19件を削除し、**設備台帳から直接ジョブを起票する**ように変える:

```
いまの流れ:  equipment → schedules（写し） → jobs
提案の流れ:  equipment ─────────────────→ jobs
             （更新予定年の leadDays 前に、その場で起票する）
```

- 更新予定年は既に `renewalPlan` が計算している。起票の判断もそこでできる
- **30年後の予定を今から表に置く必要がない**。近づいたら現れる
- 設備台帳で耐用年数を変えたら、起票のタイミングも自動で追随（写しが無いので）

**削減: 19件。** 定期作業は「繰り返す運用作業」だけになる。

### 副次効果

今日見つかった「写しのズレ」（エアコン12年 vs 台帳20年）のような事故が、
構造的に起きなくなる。写す先が無いため。

## 2. 提案B — 事務8件を「予定」ではなく「期限」として扱う

保険の更改・固定資産税・契約の判断は、**業者に頼む作業ではない**。
予算もジョブも発生せず、必要なのは「その月が来たら思い出す」ことだけ。

| 作業 | 本来の置き場 |
|---|---|
| ビジネスキーパーの更改（2棟） | **費用カード**（保険の契約期限） |
| GKすまいの保険の更改（2棟） | 同上 |
| 固定資産税の納税通知書を確認（2棟） | **費用カード**（税の期限） |
| 運営委託契約（AIRSTAR）の更新可否 | **契約書類カード**（expiresAt から導出） |
| Airstarとの契約整備（六本松前） | 同上 |

契約書類カードには既に `expiresAt` があり、**期限は導出できる**。
毎朝の点検メールに「今月が期限の契約」を出せば、定期作業に置く必要がない。

**削減: 8件**（ただし移し先の実装が要る。2〜3時間）

## 4. 提案D — 棟をまたぐ同一作業を1行にまとめる（保留を推奨）

同名が2棟にある作業が16組ある（雨樋・排水桝・消防設備点検など）。
1行で「対象=清川・高砂」と持てば16件減るが、**勧めない**:

- 実施月が棟で違う（消防設備点検は清川5月・高砂7月）
- 業者が棟で違いうる
- ジョブは棟ごとに立つので、結局分岐が要る

**表の読みやすさは、行を減らすより「施設で絞る」で解決すべき**（既にスイッチャーがある）。
