# 仕様書 — 快適クリーンの業者ポータル（水まわり＋屋外・1つのURL）

- 状態: **実装中（デモ）**。プレビューで確認 → 承認後に本番へ
- 起票: 2026-08-27
- きっかけ: 「快適クリーンもポータル化したい。チェックアウト日を選んで作業に入ってもらいたい」
  「4時間に収まらないから数日に分けたい」「日程調整を楽にしたい」（発注者）
- 発注者の決定: ①部位を指定する（数量も明確に） ②1ヶ月以内に終わらせる ③屋外系も同じURLに入れる

---

## 0. 結論 — 新しい仕組みは作らない。「作業を部位で割る」だけ

「1つの作業を数日に分ける」を新機能として作ると、訪問日の配列・部分完了・締切…と一気に複雑になる。
**部位ごとに別の作業として並べれば、いまの「1作業＝1日」の仕組みのまま同じことが実現する。**

```
水まわり一式（清川）        →  ・浴室
                              ・洗面台
                              ・トイレ＋鏡の研磨
屋外                        →  ・排水桝の清掃
                              ・外壁クリーニング
                              ・バルコニー排水口の清掃
```

業者は**作業ごとにチェックアウト日を1つ選ぶ**。3日に分かれるのは結果であって、
仕組みとして「複数訪問」を持たない。部位も数量も自然に明確になる（発注者の①を満たす）。

---

## 1. 画面（業者から見えるもの）

1つのURL。上から「水まわり（清川）」「屋外」の2つのまとまり。各作業に日付欄が1つ。

```
水まわり（清川）  ※最初の1件を決めてから1ヶ月以内に終わらせてください
  浴室                    [日付▼] [決定]
  洗面台                  11/19（木） 決定済み  取消
  トイレ＋鏡の研磨         [日付▼] [決定]

屋外
  排水桝の清掃            [日付▼] [決定]
  外壁クリーニング         [日付▼] [決定]
  バルコニー排水口の清掃    [日付▼] [決定]
```

- 日付は**チェックアウト日（11:00〜15:00）から選ぶ**。植栽と同じ窓＝在庫を壊さない
- 同じ日に複数の作業を入れてもよい（業者の判断。こちらで縛らない）
- 完了報告は作業ごと。写真は before / after

---

## 2. 期限（発注者の②）

**水まわりのまとまりだけ**、最初の1件を決めた日から**1ヶ月**を期限にする。

- 画面: 期限を過ぎる日付は選べない（`max` で塞ぐ）
- 見張り: 期限までに全部が終わっていなければ、毎朝の点検メールに載せる
- 屋外には期限を置かない（急ぐ性質ではない）

「1ヶ月以内」は運用の目安であって契約ではない。**破っても自動では何もしない**——
気づける状態にするだけ（fail-closed の原則のまま）。

---

## 3. データ（どこが正本か）

作業の一覧は **`settings/kaiteki.tasks`** に置く。コードに書かない＝**デプロイなしで増減できる**。

```
settings/kaiteki
  token, notifyTo, notes          … 他のポータルと同じ
  deadlineDays: 30                … 水まわりの期限
  tasks: [
    { key, label, group, prop, propLabel }   … group は "水まわり" / "屋外"
  ]
```

ジョブには `taskKey` を持たせ、同じ作業を二重に取れないようにする。
費用は作業ごとに実額を入れる（水まわり一式 ¥40,000 は、検収のときに1件へ入れる）。

---

## 4. やらないこと

- **訪問日の配列・部分完了の管理**（部位で割れば要らない）
- **在庫のブロック**（チェックアウト日の窓なので不要）
- **屋外と水まわりで画面を分ける**（同じ業者なのでURLは1本・発注者の③）
- **期限の自動催促を業者へ送る**（気づくのは人。急かすかどうかは人が決める）
