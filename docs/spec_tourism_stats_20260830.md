# 仕様書: 観光客数の推移カード（分析）— 月次インバウンド定点の自動化

- 起票: 2026-08-30 発注者「分析カテゴリーに『観光客数の推移』を作り、月次で数字を取りまとめる自動化を仕込みたい」
- 状態: **承認待ち**（承認後に着工）
- 担当: 共有部スレッド（ナビ追加を含むため）。カード本体は新規 `tourism.html`＋`tourism.js`

## 1. 何を作るか

福岡のインバウンド動向を**月次の定点**として台帳に積み、カードで推移を見る。
自社の稼働（revenue.occ）と並べて「市場が伸びているのに自社が落ちていないか」を一目で判定できるようにする。
AirDNA定点（半年）の月次版という位置づけ。

## 2. データ源と自動化の実現性（正直な評価）

| 源 | 中身 | 月次 | 自動化 |
|---|---|---|---|
| **観光庁 宿泊旅行統計調査** | 福岡県の外国人延べ宿泊者数 | ○（約2ヶ月遅れ） | **◎ e-Stat API で機械取得できる** |
| **出入国管理統計（法務省）** | 福岡空港・博多港の外国人入国者数 | ○（約2ヶ月遅れ） | **◎ 同じ e-Stat API** |
| FCVB 福岡市観光データ | 上記の市版まとめ | ○ | △ Webページの体裁依存＝**壊れやすい。自動化しない**。必要月だけ取込パイプ（スクショ→AI読取→検収）で入れる |
| 福岡県観光入込客推計調査 | 県の総合値 | ×（年1回） | 年1回、手で1行入れる（検収経由） |

**方針: e-Stat API の2系統だけを自動化する。** 政府統計の正式APIで、体裁変更に強い。
FCVBのスクレイピングはやらない——ページ構造が変わるたびに沈黙で壊れる類のもので、
既に持っている取込パイプ（メール転送→AI→検収）がそのまま受け皿になる。

**前提（発注者の作業・5分）:** e-Stat API の利用登録（無料・メールアドレスのみ）で appId を取得し、
Secret Manager へ登録する（`ESTAT_APP_ID`）。AIはキー値を扱わない——登録手順だけ案内する。

## 3. 台帳（SSoT）

新コレクション **`tourismStats`**（一次事実のみ・導出は保存しない）:

```
{ month: "2026-06",            // 対象月
  metric: "stay" | "entry",    // stay=外国人延べ宿泊者数(福岡県) / entry=外国人入国者数(福岡空港+博多港)
  value: 123456,               // 人泊 or 人
  source: "e-Stat 宿泊旅行統計調査 表番号…",   // どの統計のどの表か
  fetchedAt: ISO日時 }          // いつ取ったか
docID = `${metric}-${month}`   // 冪等（再実行しても二重にならない）
```

- 手入力（FCVB・県年次）は取込パイプ経由＝検収で同じ形に落とす（metric を増やす場合は schema.md に足してから）
- schema.md に追記（機械検査の対象に自動で入る）

## 4. 自動実行

- `agencyDaily` に月1回の step（毎月5日に実行・冪等なので何度走っても安全）:
  e-Stat API から直近12ヶ月ぶんを取得 → `tourismStats` へ create/merge
- 失敗したら step が例外＝heartbeat が止まり、点検メールと今日ボードに出る（既存の見張りに乗せる。新しい通知経路は作らない）
- health に1検査: 「観光定点の鮮度」——最新月が3ヶ月以上古ければ warn（統計の発表遅れ＋1ヶ月の余裕）

## 5. 画面（tourism.html — 分析カテゴリ「観光客数の推移」）

- **上段: 推移グラフ（直近24ヶ月）** — 宿泊者数と入国者数の2本。SVGで自前描画（ビルド無し方針のまま。外部ライブラリを入れない）
- **中段: 前年同月比の表** — 月／宿泊者数／前年比％／入国者数／前年比％。前年比が計算できない月は「—」
- **下段: 自社との突合** — 同じ月の自社稼働（revenue.occ・清川/高砂）を並べる。
  「市場の前年比」と「自社稼働の前年差」が逆方向の月に印を付ける（＝市場のせいにできない月）
- 正本は Firestore、画面は表示だけ（AirDNAカードと同じ流儀）。AIの READABLE に `tourismStats` を追加——質問窓で「福岡のインバウンドは伸びてる？」に答えられるようにする

## 6. やらないこと

- FCVB・県サイトのスクレイピング（壊れやすい）
- 将来予測（このカードは観測の定点。予測は資金繰りカードの領分）
- 市区町村・国籍別の深掘り（まず県計。必要になったら metric を足す）
