# yah.OS を「プロの画面」に見せるための改善提案（2026-09-05）

発注者の問い:「プロフェッショナルなウェブサイトと比べると見劣りする。改善点を」。
ガイドライン 1.9.0 と実画面・os.css を突き合わせて実測した。

**結論: 見劣りの原因は色やコントラストではない**（補足文字 7.46:1・リンク 9.71:1 と
数値は健全）。**足りないのは「階層・状態・動き」の3つ**——値がバラつき、
押した感触が無く、待ち時間が素っ気ない。Stripe や Linear が上手いのはここ。

## 実測（2026-09-05・os.css と主要カード）

| 指標 | 実測値 | プロの水準 |
|---|---|---|
| os.css の生の色指定 | **71種類** | トークン10〜15個に集約 |
| CSS変数（var()）の使用 | 19箇所のみ | 色・余白・角丸は全部変数 |
| transition の定義 | **全体で3箇所** | 押せるものすべてに |
| インラインstyle | properties.js **144**・reports 46・personal 33 | 原則ゼロ |
| 角丸 | 6px / 8px / 10px / 999px が混在 | 2段階＋ピル |
| ホバー行・選択行の定義 | なし（row-click はカーソルのみ） | 必須 |
| 読み込み中の表示 | 「ログインすると表示されます」の素テキスト | スケルトン |

## 提案（効果順・番号は優先度）

### P1. デザイントークン化 —— 71色を var(--) 十数個へ

**一番効く。** いま os.css は生の hex が71種類。黄系4種の割れ（既知のズレ§4）も
「値を直接書くから増える」のが根因。§4 の表をそのまま変数にする:

    :root {
      --bg: #000;            --line-1: #1c1c1c;  --line-2: #262626;
      --panel: #101418;      --panel-line: #1e2630;
      --ink: #fff;           --ink-2: #9a9a9a;   --ink-3: #7d8894;
      --ok: #63d297;  --warn: #ef4444;  --hold: #e0b050;  --accent: #6ea8fe;
      --r-s: 6px;  --r-m: 10px;                  /* 角丸は2段階＋999px */
      --sp-1: 4px; --sp-2: 8px; --sp-3: 12px; --sp-4: 16px; --sp-6: 24px;
    }

- **CIで守れる**: designcheck に「トークンブロックの外の生hexはラチェット」を足す
  （金額焼き込みと同じ方式。71 → 触るたびに減らす）
- 黄系4種の統一・囲み色の割れ（§9の宿題）が、この作業の中で自然に消える

### P2. 数字の階層 —— 金額が全部同じ大きさ

BSも家族ファンドも、**¥336,083,548 と行ラベルがほぼ同じ級数**。プロのダッシュボードは
「その画面の結論の数字」を大きく、説明を小さくする。

- KPI帯（いまの `.kpi`）の主数値を **1.4〜1.6rem・font-weight 650**、ラベル 0.72rem に
- 表の合計行（`.tot`）は 0.95rem のまま、**上に太い罫（2px）**で「ここから合計」を見せる
- 等幅数字（tabular-nums）は既にある——**全金額列に漏れなく**（検査に足せる:
  「¥を含む td/spans に tabular-nums が効いているか」）

### P3. 状態の設計 —— ホバー・選択・フォーカス・無効

「押した感触が無い」最大の理由。定義がそもそも無い:

| 状態 | 提案 |
|---|---|
| 行ホバー | `tr:hover { background: #0d1117 }`（row-click の行のみ） |
| 選択中の行 | 左に 2px の `--accent` 縦線＋背景 `#101822`。いまは選択が消えると分からない |
| focus-visible | `outline: 2px solid var(--accent); offset: 2px` を全ボタン・タブ・行に |
| 無効 | 現状の opacity .35 でよい（実測 1.74:1 だが無効は例外規定） |

### P4. 動き —— transition 3箇所は「動かない画面」

- **押せるものすべてに `transition: background .12s, color .12s, border-color .12s`**。
  120ms・easeのみ。それ以上の演出（スライド・バウンス）は入れない——運用画面の品位
- タブの下線は `transform` でなくてよい（点滅しなければ十分）
- `prefers-reduced-motion` で全部止める1行を必ず添える

### P5. 待ち時間 —— スケルトン

「ログインすると表示されます」「読み込み中…」の素テキストが一番「手作り感」を出す。
- os-core に `skeleton(rows, cols)` を1つ（薄いグレーの帯がゆっくり明滅・1.2s）。
  cachePaint が効く前の初回だけ出す。**文言のバリエーションを作らない**
- ログイン前は現状の文言でよい（スケルトンを出すと「壊れて見える」）

### P6. インラインstyleの根絶 —— 223箇所

properties.js 144・reports 46・personal 33。値がここに散っているかぎり P1 は完成しない。
- `style="font-size:.82rem"` の類を `.t-s` などのユーティリティ数個に回収
- **ラチェットで検査**（designcheck に `style="` の件数基準を足す）。一斉置換はしない——
  触ったカードから減らす（注記の規律と同じ運用）

### P7. 細部の統一（小さいが目につく）

- 角丸を `--r-s`（部品）/`--r-m`（パネル）の2段階に。8px の warnbox は 6px へ
- BSカードの「見出し帯」（資産=青/負債=赤。2026-09-04 に別スレッドが導入）は
  **ガイドライン未掲載**。良い形なので §6 に「集計パネルの見出し帯」として正式化するか、
  1カード限りの例外なら撤去するか、どちらかに決める——中間が一番見劣りする
- 左ナビの選択中カードに背景だけでなく左縦線 2px（P3 と同じ文法）

## やらないこと（提案の外）

- 明るいテーマ・ブランド外の色・新しいWebフォント（§0 の上位規定に反する）
- グラフライブラリの導入・アニメーションの演出
- 顧客が見る面（yah.homes）への波及——これは社内OSの話

## 進め方

P1→P3→P2 の順で1枚のカード（BS）に当てて見本を作り、発注者確認 → os.css へ展開、が安全。
**os.css・designcheck・ガイドラインはデザインスレッド管轄**——この文書は提案まで。
採択されたら、ガイドラインに §を足してから実装する（文書に無い検査を作らない）。

## 再仕分け（2026-09-06・発注者指示「P0/P1 に仕分け直して」）

BSカードでの見本→採択→ガイドライン 1.10.0/1.10.1 化までが済んだ時点での棚卸し。

### 済んだもの（ガイドラインと検査に載った）

トークンの器（os.css :root＋生hexラチェット47ファイル）／数字の階層／行そろえ
（--row-h・帯固定・合計の向かい合わせ）／状態と動き（120ms・focus-visible）／
