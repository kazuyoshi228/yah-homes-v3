# 仕様書 — 定期作業を編集できるようにする（周期のヶ月統一・業者は台帳から選択）

- 状態: **提案・承認待ち**
- 起票: 2026-08-25
- きっかけ: 「編集できるようにしたい。周期の単位はヶ月で、前回実施日程。業者は業者台帳から選択」（発注者）
- 担当カード: メンテナンス（maintenance.html）＋ schedules 周りのサーバ

---

## 1. 先に見つかった不整合（この仕様の出発点）

`ledgerId` で設備台帳と紐づく11件の `everyYears` は、**設備台帳の実効年数の写し**になっている。
同じ数字を2か所に持っているため、**すでに2件ズレている**:

| 作業 | schedules.everyYears | 設備台帳の実効年数 | |
|---|---:|---:|---|
| エアコンの更新 4台（清川） | 12年 | **20年** | ズレ |
| 防水・外壁塗装（足場共・清川） | 12年 | **15年** | ズレ |
| 他9件（FRP防水・外構・給排水管・換気・火災警報器・給湯器・シロアリ・洗濯乾燥機・屋根） | — | — | 一致（写し） |

2026-08-24 に実効年数の上限を 20→30年 に変えたとき、更新計画の14件は同時に動いたが、
**この11件の everyYears は動いていない**。写しである以上、必ずまた開く。

---

## 2. 結論 — 「表をSSoTにする」のではなく「SSoTである列だけ編集可にする」

| 列 | 正本 | この画面 |
|---|---|---|
| 作業名 / 実施月 / 前倒し日数 / 区分 / 予算 / 有効・無効 / メモ | **schedules** | **編集可** |
| 業者 | **vendors**（台帳） | **選択のみ**（vendorId を持つ。名前は台帳が正本） |
| **周期（ledgerId あり・11件）** | **equipment**（耐用年数 × 使用強度、上限で頭打ち） | **読み取り専用**＋「設備台帳へ」リンク |
| 周期（ledgerId なし・26件） | **schedules** | **編集可** |
| **前回実施日** | **jobs**（検収済みの最新）／無ければ equipment.installedAt | **読み取り専用**（保存しない） |
| 次回（自動） | 前回実施日 ＋ 周期 から毎回計算 | 読み取り専用 |

周期まで編集可にすると、いま起きているズレを**機能として固定**することになる。

---

## 3. 周期の単位をヶ月に統一する

現在: `everyYears`（年）＋ `months`（実施月の配列）の2本立て。
四半期（3ヶ月）・隔月（2ヶ月）が表現できず、清掃系と更新系で物差しが違う。

変更後: **`everyMonths`（ヶ月）に統一。**

- 年1回 → 12 ／ 半年 → 6 ／ 四半期 → 3 ／ 20年 → 240
- `months`（何月にやるか）は**残す**。周期と実施月は別の情報のため
  （例: 12ヶ月周期で実施月=11月 ＝ 毎年11月）
- `everyYears` は**読み取り互換のため当面残し**、`everyMonths` を優先。
  全件に `everyMonths` が入ったら `everyYears` を削除（別作業）

### 移行（37件・1回だけ実行）

```
everyMonths = everyYears × 12          … ledgerId なしの26件
everyMonths = 設備台帳の実効年数 × 12   … ledgerId ありの11件（＝写しを捨てて導出に置き換える）
                                          これでエアコン・外壁塗装のズレも同時に解消する
```

`everyYears=99`（単発作業＝繰り返さない）は `everyMonths=0` とし、画面では「単発」と表示する。

---

## 4. 前回実施日の導出

```
1. jobs から「この schedule に紐づく verified（検収済み）の最新」を探す → その実施日
2. 無ければ、ledgerId があれば equipment.installedAt（設置年月）
3. どちらも無ければ「—」
```

次回（自動） ＝ 前回実施日 ＋ everyMonths。ただし実施月（months）が指定されていれば、
その月に丸める。**保存しない**（今の「次回（自動）」の考え方をそのまま踏襲）。

---

## 5. 画面（メンテナンス > 定期作業）

- タブ列を **2パネル目へ縦に配置**（他カードと同じ側面リンク方式）
- 表の列: 作業 ／ **周期（ヶ月）** ／ 実施月 ／ 業者 ／ 予算/回 ／ **前回実施** ／ 次回（自動） ／ 状態
- 編集は**行クリック→右パネル**（3パネル目に編集欄を出す既存の型に合わせる）。
  表のセル直接編集にはしない（誤入力が保存に直結するため）
- 業者は **`<select>`（vendors から生成）**。自由入力にしない＝台帳が正本
- 周期が読み取り専用の行は、入力欄を出さず「設備台帳で決まります（◯年）→ 台帳へ」と表示

---

## 6. 保存の経路

既存の `saveDoc`（col=schedules）をそのまま使う。新しいAPIは作らない。
保存できる項目を**許可リスト**で絞る（勝手な項目が増えないように）:

```
title / prop / category / everyMonths / months / leadDays / vendorId /
budget / active / needsDecision / manualOnly / statutory / note
```

`ledgerId` は画面から編集させない（紐づけの張り替えは事故が大きい）。

---

## 7. やらないこと

- **周期を2か所に持つこと**（これが今回の出発点）
- **前回実施日を schedules に保存すること**（jobs が正本）
- **業者名の自由入力**（vendors 台帳が正本）
- **表のセル直接編集**（右パネル方式に統一）
