# 指示書: 不動産DBの四半期更新（2026-09-03）

**関数は書いた。動かすのに必要なのは、APIキーの登録だけ。**

## 何が動くか

`landCompsSync`（Cloud Functions・`functions/src/landCompsSync.ts`）

- **実行: 1・4・7・10月の10日 4:00（JST）** ＝ 四半期ごと
- 国交省の取引価格情報から、福岡市中央区の**土地の成約**を取り込む
- 直近4四半期を見る（公表が2四半期ほど遅れるため、余裕をみている）
- 結果は `syncLogs/landComps-YYYY-MM-DD` に残る

## 動かすのに必要なこと（発注者）

**不動産情報ライブラリのAPIキーを Secret Manager に登録する。**

```
firebase functions:secrets:set REINFOLIB_API_KEY --project yah-homes
```

登録したら、次のデプロイで有効になる。

**キーが未設定のあいだは、取得せずに「未設定」を記録して静かに終わる。**
申請中に毎回エラー通知が飛ぶのを避けるため、わざとそうしてある。

## 取り込む対象と、取り込まないもの

| | |
|---|---|
| 取り込む | `Type` が「宅地(土地)」の行だけ |
| 取り込まない | 土地＋建物、中古マンション、農地、林地 |

**理由**: 建物付きの取引は、単価の意味が変わる。同じ㎡単価でも建物代が混ざるため、
土地の相場としては比較できない。

## 種類を混ぜないこと

`source` で必ず分けている。**これは設計の中心にある約束**である。

| source | 中身 |
|---|---|
| `mlit` | 成約（実際に売れた値段） |
| `kouji` | 地価公示（1月1日の鑑定評価） |
| `chousa` | 地価調査（7月1日の鑑定評価） |
| `freins` | 売出（売れた値段ではない） |

2026-09-02 に高砂で調べたところ、**売出は成約の2〜3倍、公示ですら2025年の成約の1.6倍**だった。
混ぜると相場を誤る。

## 手で入れたぶんの扱い

2026-09-02〜03 に画面から取った 1,555件は、そのまま残す。
`fetchedAt` で入れた日が分かる。自動更新が同じIDに当たれば上書きされ、
当たらなければ両方残る——**成約は同じ取引が二度公表されないので、重複は起きない**。
