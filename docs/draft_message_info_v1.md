# 顧客メッセージ用情報 — 推奨内容ドラフト v1

- 起票: 2026-08-19（発注者依頼「おいておいた方が良いと思われる情報を下書きMDで」）
- 状態: **ドラフト＝投入待ち**。発注者が内容を確認・修正のうえ、/admin/properties/{棟}/#message に貼る
- 投入先: `/admin/properties/kiyokawa/#message`・`/admin/properties/takasago/#message`（正本: property_facts/{prop}.messageInfo）

## 書き方の原則（重要）

1. **SSoTにある数字は書かない。** チェックイン時刻・住所・駐車場・キャンセル日数・宿泊税などは
   AIが【施設情報】として自動で参照する（functions aiFactsBlock）。ここに写すと二重管理になる。
2. **ここに書くのは「運用の方針と文面」だけ。** 誰に・いつ・どの経路で案内するか、AIがどう一次回答するか。
3. **暗証番号・Wi-Fiパスワード等の実値は絶対に書かない**（案内の経路だけを書く）。
   ※Wi-Fi実値はチャット用情報側の既存運用に従う。
4. 「（要確認）」の行は運用実態に合わせて発注者が確定してから投入する。
5. 両棟共通の内容がほとんどのため、**同じ表を両棟に貼る**（棟差がある行だけ変える）。

## 分類1: 名簿・チェックイン前

| 設問 | 回答（案） |
|---|---|
| 名簿の提出をお願いする文面 | ご宿泊者名簿のご提出をお願いいたします。ご提出いただくと、前日に入室のご案内（暗証番号を含む）をお送りできます。フォームのURLは予約確定メールに記載しています。 |
| 暗証番号を聞かれたら | メッセージやチャットではお伝えしません。名簿ご提出後、前日のご案内メールでのみお送りします。前日になっても届かない場合は迷惑メールフォルダをご確認いただき、見つからなければその旨ご返信ください（スタッフが対応します）。 |
| 入室案内メールが見つからない | 迷惑メールフォルダの確認をご案内し、それでも無ければ「担当者が再送しますので少々お待ちください」と回答（AIは番号を再案内しない）。 |
| 早いチェックイン（アーリーチェックイン）を頼まれたら | 清掃の都合上、原則お受けしていません。前の予約状況によっては可能な場合があるため「担当者が確認してご案内します」と回答。 |
| チェックイン前の荷物預かり | お受けしていません。チェックイン時刻以降のご入室をお願いする。（要確認: 近隣のコインロッカー等を案内するか） |
| 当日の到着が遅くなる連絡 | セルフチェックインのため深夜のご到着でも問題ない旨を伝え、安心していただく。 |

## 分類2: 入室トラブル

| 設問 | 回答（案） |
|---|---|
| キーボックスが開かない・場所が分からない | 入室案内メールの手順（写真付き）を再確認いただく。解決しなければ運営の電話（施設情報の緊急連絡先）へ誘導し、「スタッフにも共有しました」と添える。 |
| 暗証番号を入れても開かない | 番号の再入力手順（一度リセットしてゆっくり）を案内し、解決しなければ電話へ。**AIは番号そのものを書かない。** |
| 鍵を中に置いたまま閉め出された | 運営の電話へ誘導（緊急対応）。 |

## 分類4: 変更・返金・キャンセル（すべてエスカレーション対象）

| 設問 | 回答（案） |
|---|---|
| 返金の一次回答 | 担当者が確認してご案内します。**AIは金額・可否・時期を約束しない。** |
| 日程を変更したい | 空き状況と料金差の確認が必要なため「担当者が確認してご案内します」。キャンセルポリシーの期限（施設情報）だけは事実として案内してよい。 |

## 分類6: 緊急・トラブル

| 設問 | 回答（案） |
|---|---|
| 水漏れ・破損・設備故障 | お怪我がないか確認→応急の止め方（分かる範囲）→「スタッフに共有しました。担当者からすぐご連絡します」。破損の弁償話は金額を約束せず担当者へ。 |
