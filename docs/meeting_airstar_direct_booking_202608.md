ご相談したいのは、**代金の受け取り方の整理**と、**宿泊者名簿の運用**、そして **Beds24 の設定変更1件**です。

## 3. どんな仕組みか

```
お客様がサイトで日付と人数を選ぶ
  → その場で空室と総額が表示される（Beds24 の在庫・料金をそのまま表示）
  → Googleアカウントでログイン → お客様情報・ハウスルール同意
  → クレジットカードでお支払い
  → Beds24 に予約が入る（＝運営会社様の画面に、他OTAと同じように表示されます）
```

**料金は Beds24 の設定がそのまま使われます。** サイト側で価格を持たないため、運営会社様が Beds24 で料金を変更されれば、Airbnb・Booking.com と同時に直販サイトにも反映されます。二重管理は発生しません。

**現在の設定内容（サイトに表示中）**
- 5名まで同一料金／6名目以降 お一人1泊 ¥5,000
- チェックイン 15:00〜／チェックアウト 〜10:00（時間の制限なし・キーボックス受け渡し）
- 無料キャンセルは**チェックイン7日前**まで
- ハウスルール: パーティー・イベント不可／申告人数厳守（タオル・寝具は申告人数分）／玄関に屋外防犯カメラ／屋内禁煙

## 4. 運営会社様にお願いしたいこと

### ① 代金の受け取り方の整理（契約に1条項）

直販のお支払いは当社（ボンファイア）の決済口座で受け取ります。整理としては、**当社が予約受付と代金の代理受領を行い、宿泊サービスの提供は運営会社様**、という形にさせていただきたく存じます。OTA と同じ構造です。

- 月次のご精算は、これまでの帳票に「直販」の行が増えるだけです。
- 運営委託契約に代理受領の条項を1つ追加させてください（当社で文案をご用意します）。

### ② 宿泊者名簿について（現状のご確認）

**Airbnb のお客様の宿泊者名簿（ご住所・外国籍の方の旅券確認）は、現在どの仕組みで取得されていますか。**

直販のお客様にも同じ運用を適用いただけるようであれば、**当社側では名簿情報を一切保有しない形**で進めます（旅館業の許可名義は運営会社様のため、その方が管理が明快です）。

もし直販のお客様向けに取得手段がないようでしたら、当社のフォームで取得して運営会社様へお渡しする形も用意できます。

### ③ 直販での例外時の役割分担（追加のご負担はほぼありません）

決済まわりは自動化・当社対応としており、**運営会社様に新たな作業はほとんど発生しません**。

| ケース | 対応 |
|---|---|
| カード決済が通らなかった | Stripe からお客様へ自動通知。人の対応は不要です |
| お客様都合のキャンセル | お客様がマイページで7日前まで自己完結。返金も自動です |
| 日程変更のご相談 | 当社が受け、空室確認のうえ対応します |
| カード会社からの照会（チャージバック） | 当社が対応します。ごく稀に**「このお客様は実際にご宿泊されましたか」の確認**をお願いする場合があります |
| 到着予定時刻 | お客様がご入力された場合、情報として共有いたします |

実質的なお願いは**最後の宿泊事実の確認のみ**で、頻度も年に数件あるかどうかという想定です。念のため、役割とご連絡先をまとめた1枚の手順書を当社で用意します。

### ④ Beds24 の設定変更（1件）

| 内容 | 目的 |
|---|---|
| 清川の最大人数を **7名 → 8名** に変更 | シングルベッド追加に伴う定員拡張。現在8名で検索されると表示されません |

※ API トークンの発行は当社側で対応いたします。

あわせて、**テスト用の物件を1つ作成**させていただきます（OTA には接続しません）。本番のカレンダーを汚さずに動作確認を行うためのもので、確認後に削除します。
