# メンテナンスカードの二重スクリプトを解消する（2026-08-28・未承認）

対象: `yah-os/maintenance.html`（1,334行）
担当: メンテナンスカードのスレッド
きっかけ: 共有部スレッドから「1,334行の分割は担当外」として回付された件への回答

## 結論: ファイル分割はしない。モックを消す

分割は**やらない**ことを提案する。理由は2つ。

1. **`1カード＝1HTML` はこのリポジトリの決めごと**（yah-os/CLAUDE.md「地図」）。
   分割すると、並行スレッドが「どのファイルが誰の担当か」を判断できなくなる。
   行数を減らす目的なら、分割ではなく**消す**ほうが筋が通る。
2. **行数の問題ではない。** 1,334行のうち **246行が、ログイン前にだけ表示される作り物**で、
   ログイン後は本物のデータで上書きされる。同じ画面を2通りの方法で描いている。

## いまの構造

| ブロック | 行 | 中身 |
|---|---|---|
| `<style>` | 13〜59 | このカード固有のCSS |
| `<script>`（素） | 303〜576 | タブ切替（27行）＋ **モックのカレンダー（246行）** |
| `<script type="module">` | 578〜1332 | 認証・API・本物の描画 |

素のスクリプトが分かれているのは、**`os-core.js` を import できないため**。
モジュールは defer 相当で後から走るので、「ログイン前でも画面の骨格を出す」目的で置かれた。

## 消すもの（246行）

素のスクリプト内の以下は、モジュール側の `renderCalendar()` / `openLiveJob()` / `renderVendors()` と
**同じ画面を、偽のデータで描いている**。

- `NOW = { y: 2026, m: 8 }` … 「今」を2026年8月に固定した定数（330行付近）
- `RULES` … 作り物の定期作業（外構掃除・消防設備点検など）
- `stateOf()` / `openJob()` … 作り物の状態判定とジョブ詳細
- `render()` … 作り物のカレンダー描画
- `VEN_DETAIL` … 作り物の業者詳細

### なぜ消すのか

- **二重の正本。** カレンダーの描き方が2つある。片方を直してもう片方を忘れる事故は、
  すでに定期作業タブで起きている（2026-08-25: 見出し8列に対しモック行6セルでズレた）。
  そのときは同じ理由でモック行を撤去し、「ログインすると表示されます」に置き換えた。
  **カレンダーと業者台帳だけが取り残されている。**
- **「今」が2026年8月に固定されている。** 年をまたぐと、ログイン前の画面が過去を指す。
- **実在しない金額・業者名がHTMLに書かれている。** CLAUDE.md の
  「HTMLに実在の金額・係数を書かない」の趣旨（画面とデータの正本を混ぜない）に反する。

### 置き換え先

定期作業タブと同じ扱いに揃える。

```html
<tbody><tr><td colspan="N" class="dim">ログインすると表示されます</td></tr></tbody>
```

## 残すもの（素のスクリプト・約27行）

- `TABS` / `PER_PROP` / `applyScope()` / `window.showTab`
- `window.PROP_KEY` / `window.PROP_LABEL_OF`（表示名↔FirestoreのIDの対応表）

ログイン前でもタブが切り替わることには意味がある（何のカードか分かる）。
`window.` 経由の受け渡しは、**素のスクリプトとモジュールの唯一の接点**として残す。

## やらないこと

- **素のスクリプトの全廃**（ログイン前にタブが死ぬ）
- **モジュール側の描画ロジックの変更**（今回は削除だけ。動作を変えない）
- **`os.css` / `os-core.js` / `os-nav.js` への波及**（共有部の担当）
