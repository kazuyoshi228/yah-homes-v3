# 提案書 — 業者ポータル（niwa方式）を他の業者へ広げる

- 状態: **提案・未着手（承認待ち）**
- 起票: 2026-08-25
- きっかけ: 「このツール、他の業者との連携にも使えそう」（発注者）
- 前提: 植栽版（花屋アン・清川）が本番稼働中。定期作業37件・業者台帳6社を実査した上での仕分け

---

## 0. 結論

**そのまま横展開できるのは「屋外・短時間」の作業だけ。** 定期作業37件を仕分けると:

| 型 | 件数 | そのまま使えるか |
|---|---|---|
| A. 屋外・短時間（チェックアウト日の11〜15時に収まる） | **6件** | **○ そのまま** |
| B. 屋内・要鍵（ゲストと完全に分離が必要） | 9件 | △ 拡張が要る（後述） |
| C. 大規模工事（足場・数日〜数週間） | 8件 | ✕ 対象外 |
| D. 事務・財務（業者が要らない） | 14件 | ✕ 対象外 |

**なぜ割れるか**: 植栽版が成立しているのは「**確定済みの退去**と**16時チェックイン**に挟まれた窓は、
後から予約が入っても壊れない」という一点による。屋内作業はこの窓に収まらず、
**在庫を止めないと安全に作業できない**——これは設計が変わる。

---

## 1. A型 — そのまま使える（6件）

| 作業 | 棟 | 業者 |
|---|---|---|
| 雨樋・軒樋の清掃 | 清川・高砂 | **未定** |
| 排水桝の清掃 | 清川・高砂 | **未定** |
| 外壁クリーニング | 清川・高砂 | **未定** |

屋外で完結し、鍵が不要で、清掃スタッフと併存できる。植栽と同じ窓・同じ画面で回せる。

**ただし6件すべて業者が未定。** ツールを広げる前に、まず業者を決める必要がある。
逆に言えば「業者さえ決まれば、その日から自走する」状態にはできる。

---

## 2. B型 — 屋内作業（拡張が必要・9件）

代表例: 消防設備点検（西原商会・法定・**業者決定済み**）／水回りのプロ清掃（快適クリーン・**決定済み**）／
給気口・レンジフードのフィルター清掃／家具の点検／エアコン・給湯器・洗濯乾燥機の更新

**いま業者が決まっている2社はどちらもB型**。つまり横展開の即効性はA型より
「実際に稼働している関係があるB型」の方が高い——が、そのためには2つ追加が要る:

### ① 完全空室日を出す＋Beds24に仮ブロックを書く

屋内作業は「チェックアウト日の4時間」に収まらない（消防点検は各室を回る・水回り清掃は半日）。
完全空室日を出す必要があるが、それは**販売中の在庫**なので、業者が選んだ後に予約が入ると潰れる。

→ 業者が日を選んだ瞬間に **Beds24へブロックを書き込む**（＝その日を売らない）。
仕様§4で「Beds24への書き込みはしない」と決めたが、B型を入れるならここを見直すことになる。

### ② オーナーの承認を挟む（自動確定にしない）

在庫を止める＝機会損失（1泊¥40,000〜60,000）。植栽のような自動確定は危険。

```
業者が候補日を選ぶ → オーナーへ通知「◯/◯を止めますか？」→ 承認したらBeds24をブロック
                                                    → 却下なら業者に別日を促す
```

A型（自動確定・在庫に触らない）とB型（承認制・在庫を止める）は**別の流れ**として作る。
1つの画面に混ぜると、誤って在庫を止める事故が起きる。

---

## 3. C型・D型 — 対象外

- **C（大規模工事）**: 防水・外壁塗装（足場）、屋根の葺き替え、給排水管の更新、外構工事、FRP防水など。
  日程は見積・工程表とセットの交渉で決まる。カレンダーから日を選ぶ性質のものではない。
  既存の**メール経路（dispatcher＋定型メール）が正しい道具**
- **D（事務・財務）**: 保険の更改、固定資産税、契約の判断など。業者が要らない

---

## 4. 広げるときの作り（共通化の設計）

いまの niwa は清川・花屋アン・11〜15時が**ハードコード**。汎用化するなら:

```
settings/portals/{portalId}
  token       … 業者ごとに別トークン（1社漏れても他社に影響しない）
  vendorId    … vendors への参照（名前・連絡先は台帳が正本）
  props       … 対象の棟（複数可）
  type        … "outdoor"（A型・自動確定）| "indoor"（B型・承認制＋ブロック）
  window      … 作業可能な時間帯（A型のみ。"11:00-15:00"）
  categories  … このポータルで扱う作業区分（植栽／清掃／点検…）
```

- 画面は1つ（niwa.html）を `?t=` のトークンで切り替える。**業者ごとにHTMLを作らない**
- 通知の宛先・文面は既存の仕組み（settings.notifyTo・mailTemplates）をそのまま使う
- 「検収は人だけ」の鉄則は不変

**工数の目安**: A型の汎用化に4〜5時間。B型（Beds24ブロック＋承認フロー）に追加6〜8時間。

---

## 5. 推奨する順

1. **まずA型の業者を決める**（雨樋・排水桝・外壁クリーニング）。ツールより先に人
2. 決まったらA型を汎用化して展開（4〜5時間）。植栽で実証済みの流れをそのまま流用
3. B型は**水回りのプロ清掃（快適クリーン）1社で試す**。うまく回ったら消防点検（西原商会）へ
4. C型は広げない。メールのままが正しい

**やらないこと**: 全業者への一斉展開。ポータルは「頻度が高く・業者に日程の自由度があり・
写真報告が要る」作業にだけ効く。年1回の点検にログイン先を増やすのは、相手にとって負担が増えるだけ。
