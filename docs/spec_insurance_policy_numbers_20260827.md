## 1. わかったこと

ご契約者ページの4契約と、台帳の4件は**同じもの**。重複契約ではない。

| | ページ | 台帳 |
|---|---|---|
| 件数 | 4 | 4 |
| 内訳 | 高砂×2・清川×2 | 高砂(BK・GK)・清川(BK・GK) |
| 代理店 | 株式会社BrightReach | `agentVendorId: "brightreach"` |

住所の丸数字（`福岡県②高砂` / `福岡県①清川`）は代理店側の物件連番。
`MP12859441331` にだけ丸数字が無いのは登録順の都合とみられ、**解約漏れではない**
（同じ住所が2件ずつ出るのは 1棟につき BK と GK の2本があるため）。

### 直すべき点 — 台帳が見積のまま

| フィールド | いまの値 | 本来 |
|---|---|---|
| `status` | ~~`見積`~~ → **`契約中`（2026-08-27 更新済み）** | `契約中` |
| `policyNo` | `72762493` 等（＝**見積番号**） | `MP128594413xx`（＝証券番号） |

`quote` フィールドに同じ数字が入っており、`policyNo` に見積番号を入れたまま
契約に進んだのが原因。**証券番号で照会できない台帳になっている**ため、事故時に困る。

## 2. どのMP番号がどの契約か — 領収書の金額で確定する

ページは商品名を出さないので、**領収書の保険料**で機械的に判別できる。
台帳の年額と突き合わせるだけで一意に決まる:

| 物件 | 商品 | 年額 | 期間 |
|---|---|---|---|
| 清川 | ビジネスキーパー | ¥78,340 | 2026-01-09〜2027-01-09 |
| 清川 | GK すまいの保険 | ¥53,920 | 同上 |
| 高砂 | ビジネスキーパー | ¥81,610 | 2026-03-14〜2027-03-14 |
| 高砂 | GK すまいの保険 | ¥126,210 | 同上 |

候補は 清川＝`MP…331` / `MP…333`、高砂＝`MP…332` / `MP…334` の2通りずつ。
**同じ物件の2本は金額が大きく違う**（清川 78,340 vs 53,920／高砂 81,610 vs 126,210）ので
取り違えようがない。

> 金額が台帳と1円でも合わない場合は、**契約時に条件が変わった**ということ。
> その場合は番号を入れる前に、変わった条件（保険金額・特約・免責）を先に確認する。
> 合わない金額のまま `契約中` にすると、間違った前提で更改の判断をすることになる。

## 3. 設定のしかた

### 3-1. `insurance/*` の4件（証券番号と状態）

各ドキュメントに対して:

```
policyNo   : "MP12859441331" 形式の証券番号（★ページの表記どおり）
quoteNo    : いま policyNo に入っている見積番号を移す（例 "72762493"）
status     : "契約中"
quote      : 削除（quoteNo に一本化。同じ数字を2フィールドで持たない）
```

- `quote` を消すのは、いま `"7276249 3"` のように**空白入りで壊れている**ため。
  見積番号は `quoteNo` に正しい形で持ち直す
- `status` の値は既存の語彙（`見積` / `契約中`）に合わせる。新しい語を増やさない

### 3-2. `settings/insurance`（新設・代理店の窓口）

事故のときに探す情報が台帳に無い。1ドキュメントにまとめる:

```
contractorId : "WRJ1H320260302"        契約者ID（ご契約者ページのログイン単位）
portalUrl    : （ご契約者ページのURL）
agentName    : "株式会社BrightReach"
agentTel     : "03-6222-7277"
agentHours   : "平日9:00〜18:00（土日祝・年末年始を除く）"
agentNote    : "ホスト向けサポートデスク。事故受付もここ"
updatedAt    : "2026-08-27"
```

**契約者情報（会社名・代表者・住所・電話・メール）は入れない。**
`properties` と会社情報に既にあり、二重管理になる。台帳に持つのは
「**どこへ連絡するか**」と「**どのIDで照会するか**」だけでよい。

### 3-3. `insurance.html`（表示）

1. 一覧の証券番号列を `policyNo`（MP…）に。`quoteNo` は詳細でのみ小さく出す
2. カード上部に事故時の連絡先を1行出す — `settings/insurance` から組み立てる
   （**電話番号を画面に書かない**。指示書 `directive_hardcoded_amounts_20260827.md` と同じ理由）
3. `status` が `見積` の行にだけ「未契約」の印を出す。今回の直しで4本とも消えるはずで、
   **印が残っていたら台帳が現実に追いついていない**という警報になる
