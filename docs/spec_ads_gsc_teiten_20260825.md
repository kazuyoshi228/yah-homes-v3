# 仕様書 — Google広告費とGSCの定点蓄積

- 状態: **提案・未実装（承認待ち）**
- 起票: 2026-08-25・定期レポート担当スレッド
- 前提: BaaSファースト・SSoT化必須。既存の ga4Daily / bookingDaily と同じ作法に揃える

---

## 0. 共通の原則 — 日割りだけ保存し、週・月は計算で出す

発注者要望は「日割り・週割・月割で集約」だが、**保存するのは日次の1行だけ**にする。

| | 保存 | 出し方 |
|---|---|---|
| 日 | **○ これだけ** | そのまま |
| 週・月 | ✕ | 表示時に合算（画面のタブで切替） |

理由: 週次・月次を保存すると、日次を1日直したときに3か所を直すことになる（＝必ずズレる）。
月の途中でも「今月ここまで」が自然に出るのも導出の利点。既存カード（更新計画の年割り等）と同じ規律。

## 1. Google広告費

### 現状

- 広告APIの連携は**ゼロ**。数字は毎週手で管理画面から拾って teiten_baseline に転記している
  （§4に台湾¥2,500/日・CPA¥358 などの記録あり）
- 損益分岐CPA ¥2,200 という判断軸は既にあるのに、**実績CPAの推移が機械で追えていない**

### 経路は2つ。どちらかは「調べれば5分で決まる」

**案A（軽い・第1候補）: GA4経由**
Google広告とGA4がリンクされていれば、GA4 Data API に広告費が入っている:
`advertiserAdCost` / `advertiserAdClicks` / `advertiserAdImpressions` / `sessionCampaignName`。

- **今日作った ga4TeitenSync に列を足すだけ**。新しい鍵・SA・権限がゼロ
- 取れる粒度: 日 × キャンペーン（＝市場別。台湾/香港/韓国/SG）
- 制約: GA4の計測基準（GA4のセッション帰属）なので、**Google Ads管理画面の数字とは数%ずれる**

**案B（重い・案Aが不可なら）: Google Ads API 直**
- 必要なもの: 開発者トークン（申請・審査あり）＋OAuthリフレッシュトークン（Secret Manager）
- 得られるもの: 管理画面と完全一致。コンバージョン単位のCPAも正確
- コスト: 初期設定が半日〜。以後の運用は同じ

**判断の手順**: GA4に `advertiserAdCost` を1クエリ投げる（5分）。値が返れば案A、0/エラーなら案B。

### スキーマ（案A・adsDaily）

```
adsDaily/{date}: {
  date: "2026-08-24",
  total: { cost: 4820, clicks: 61, impressions: 1204 },
  byCampaign: { "TW_一棟貸し": { cost: 2500, clicks: 38, impressions: 720 }, … },
  source: "GA4 Data API（advertiserAdCost・property 539535968）",
  syncedAt: <serverTimestamp>,
}
```

- CPA・CPC・ROASは**保存しない**（cost ÷ CV で表示時に計算）
- CVは ga4Daily 側にある（購入・手渡し）。**広告費とCVを別コレクションに置き、画面で突き合わせる**
  ——CVの定義が変わっても広告費の記録は汚れない

### 画面（定点観測 > Google広告）

| 日付 | 費用 | クリック | CPC | 手渡し | 購入 | CPA | 市場別内訳 |

- 上部タブで **日 / 週 / 月** を切替（同じデータを合算するだけ）
- 右パネル: 直近7日 vs 前7日、**損益分岐CPA ¥2,200 に対する現在地**（teiten_baseline §4の判断軸を画面へ）

## 2. GSC（Search Console）

### 現状

- 連携ゼロ。毎週手で「7日間のクリック・表示」をメモしている（定点手順§7-3）
- **GSCのデータ保持は16ヶ月**。放置すると2025年分から順に消える——**蓄積の価値が最も高いのはここ**

### 経路（迷いなし）

Search Console API `searchanalytics.query`。SAをGSCプロパティの**ユーザーに追加**するだけ（1回・鍵不要）。
毎朝8:15に同期。GA4/広告と同じ形。

### スキーマ（3層。粒度ごとにコレクションを分ける）

```
gscDaily/{date}         : { clicks, impressions, ctr, position }          … サイト全体
gscQuery/{date}_{hash}  : { date, query, clicks, impressions, position }  … 上位100クエリ/日
gscPage/{date}_{hash}   : { date, page, clicks, impressions, position }   … 上位100ページ/日
```

- ctr / position は**GSCが返す値をそのまま保存**（自分で割らない。GSCの定義に合わせる）
- 上位100に絞る理由: 全クエリは裾が極端に長く、大半が表示1回。**判断に使うのは上位だけ**
- クエリは1日で消えるものが多いため、**日次で積む**（週次だと「いつ現れたか」が失われる）

### 取得の作法

- **3日遅れ**でデータが確定するため、毎朝「4日前〜2日前」の3日窓を取り直す（GA4と同じ思想）
- **バックフィル**: 初回に過去16ヶ月を一括取得（GSCが持っている全部）。これが最大の資産化
- 日次の全体行は必ず取れるが、クエリ行はプライバシー閾値で欠ける日がある → 件数を記録して欠測を明示

### 画面（定点観測 > 検索流入）

- 日/週/月タブ ＋ クリック・表示・CTR・平均順位の推移
- **クエリの動き**: 「新しく現れたクエリ」「順位が上がった/下がったクエリ」を前期比で自動抽出
  ——毎週手でやっている「KW昇格/降格」の判断材料が自動で出る
- ページ別: villa記事の順位、where-to-stayのCTR（判定カレンダー§6の対象）を追える

## 3. 実装順・工数

| 順 | 内容 | 工数 |
|---|---|---|
| 0 | **GA4に広告費が入っているか5分で確認**（案A/B の分岐） | 5分 |
| 1 | GSC同期（SA追加＋gscSync＋16ヶ月バックフィル） | 2h |
| 2 | 広告費同期（案Aなら ga4Sync に追記で0.5h／案Bなら別途要相談） | 0.5h〜 |
| 3 | 画面2ビュー（日/週/月タブ・突合表示） | 2h |

**推奨: 0 → 1 の順。** GSCは16ヶ月で消えるデータなので、着手が1日遅れるほど失う。
広告費は管理画面にいつでもあるため急がない。

## 4. やらないこと

- 週次・月次の集計値の保存（§0）
- Meta広告: いまは種火のみ。Google広告の型ができてから同じ形で足す
- 原本アーカイブ: 不要（両方ともAPIで再取得可能）
