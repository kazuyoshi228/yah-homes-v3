### 3-3 v4 に無かった追加実装

**二重予約の防止（重要）**
Beds24 は在庫0でもAPI経由の書き込みを受け付ける（実測：在庫が `-1` になる）。したがって在庫を守るのは自社コードのみ。宿泊各日について `inventory_locks/{prop}_{date}` を**1トランザクションで一括確保**し、1日でも取れなければ予約を成立させない（オーソリ解放）。

**空室検索の高速化**
1表示あたり6リクエスト→2リクエスト。`renderAll()` の二重発火を除去し、in-flight重複排除・AbortController・stale応答の破棄を実装。`minInstances: 1` でコールドスタート（実測 +0.77秒）を除去。

| 指標 | 改善前 | 改善後 |
|---|---|---|
| 見積りAPI uncached | 0.53〜1.32秒 | 0.46〜0.78秒（p95 0.78） |
| 見積りAPI cached | — | 0.16〜0.36秒 |
| 結果表示まで | 約1.93秒 | 約1.50秒 |

**物件ファクトSSoT**
`/admin/properties` を比較表形式に。定員・客室・水回り・設備・アクセス・人気スポット距離・チェックイン時刻を Firestore `property_facts` に集約し、ビルド時にHTMLへ焼き込む。

**確定メール（HTML・5言語）**
写真＋4カード（ご予約内容／キャンセル料／お支払い）＋CTA2種（変更・キャンセル／お問い合わせ）＋入室・場所・安全のために。キャンセル料は**金額で明示**。

## 4. 状態機械

```
QUOTE_ISSUED → PAYMENT_PENDING → AUTHORIZED → RESERVATION_PENDING → CONFIRMED
                     ↓               ↓                ↓                  ↓
              PAYMENT_FAILED      VOIDED          VOIDED           CANCELLED
                                                MANUAL_REVIEW
```

- 遷移は `transition()` の CAS（status + stateVersion）で直列化。古いタスクの上書きを防ぐ
- `fulfillBooking` の順序（**動かさない**）：在庫・料金の再確認 → 日付ロック確保 → Beds24書込 → capture → CONFIRMED
- Beds24書込に成功しキャプチャに失敗した場合のみ `MANUAL_REVIEW`（人がBeds24を取り消す）

## 5. キャンセル

### 5-1 規定（確定）
- **無料期限：チェックイン日の8日前 23:59 JST**（v4実装の「7日前 00:00」から変更。特商法・FAQ・決済画面の表記と一致させる）
- 期限後・無連絡不泊：宿泊料金の全額
- 判定は**サーバー時刻**。クライアントの時計は使わない

### 5-2 運営側（`/admin/bookings` の返金）
`/admin/bookings` の返金で、Stripe返金 → Beds24取消 → 日付ロック解放 → `CANCELLED` → 監査ログ、が一気通貫。Beds24取消に失敗した場合は返金を行わず「要対応」メールを送る。

### 5-3 セルフキャンセル（**実装済み**・2026-08-10）
仕様は `docs/spec_self_cancel_202608.md`。My Page のボタン → 返金額を明示した確認ダイアログ →
`CANCELLING` へCAS → Beds24取消 → Stripe返金 → ロック解放 → `CANCELLED` → 確認メール（5言語）。
Beds24 を先に取り消すのは、返金だけ通って部屋が残る状態を作らないため。決定事項は以下。

| # | 決定 |
|---|---|
| 1 | 無料期限を「8日前 23:59 JST」に変更 |
| 2 | 期限後のセルフキャンセルも**許可**（返金なしと明示） |
| 3 | キャンセル理由は**任意の自由記述1つ** |
| 4 | チェックイン当日・滞在中はボタンを出さず問い合わせのみ |

### 5-4 変更（日程・人数）
**P1では実装しない。**「キャンセル→取り直し」で運用する。無料期間内なら金銭的な不利益は生じない。この方針は My Page と確定メールに5言語で明記済み。

標準eコマース（`begin_checkout` → `add_payment_info` → `purchase`）＋独自イベント。`purchase` はサーバー側 Measurement Protocol で送信（離脱・広告ブロック・重複でCVが歪むため）。個人情報は送らない。
